## 二、基准层：三处被文章口径带偏

### 2.1 G1 的「refusal 当成功」半条 —— DSH 自己也没有 refusal

原报告 G1 把「max_tokens 截断」与「refusal 拒绝」并列，判定为「线上最常见的假成功」且列为最高优先。**但 DSH 的停止信号白名单里没有 refusal**：

| 证据 | 内容 |
|---|---|
| `[DSH]` `packages/llm/llm/src/types.ts:156-162` | `FinishReasonMap` = `{ 'stop', 'tool-calls', 'max-tokens', 'aborted', 'error' }` —— **五值，无 refusal** |
| `[DSH]` `packages/llm/llm-deepseek/src/translate.ts:92-94` | 适配器映射只有三支：`end_turn`/`stop_sequence` → `stop`；`tool_use` → `tool-calls`；`max_tokens` → `max-tokens` |
| `[DSH]` `packages/llm/` 全库 grep | `refusal` / `content_filter` 映射 **0 命中** |

**更值得注意的一处同形**：DSH 的终态判据与原报告批评的 HelloAI 写法**是同一个**：

```text
[DSH] packages/core/agent-loop/src/agent.ts:549  const toolCalls = message.content.filter(b => b.type === 'tool-call')
[DSH] packages/core/agent-loop/src/agent.ts:550  if (toolCalls.length === 0) return { kind: 'completed' }
```

`[实测]` HelloAI `ChatModelToolLoop.java:171` `if (assistant == null || !assistant.hasToolCalls())` —— **同一判据形态**。

**真正的差别只有一处**：DSH **在该判据之前**多出两条出口 +

- `[DSH]` `agent.ts:506` `if (finish.kind === 'error' || finish.kind === 'aborted')` → 走 `agent/request-error` waterfall，可 retry，否则抛 `LlmError`
- `[DSH]` `agent.ts:547` `if (finish.kind === 'max-tokens') return { kind: 'max-tokens' }` → **独立的终态**，且 `agent.ts:338-343` 明确「**max-tokens is sticky**」（一旦触顶，后续正常完成的步**不得**把 turn 结果降级）

⇒ **G1 的净缺口 = 「max_tokens 截断被静默当成功」这一条**；「refusal 当成功」属**双方共同未处理**，不应与前者并列定为「最高优先」。

**另有一处反向发现**：DSH 对**缺失/未识别**的停止原因的处理，正是文章反模式① 描述的形态：

```text
[DSH] packages/llm/llm/src/assembler.ts:186-188
      /** Finish reason from the `finish` chunk; `{kind: 'stop'}` when the stream ended without one. */
      get finish(): FinishReason { return this._finish ?? { kind: 'stop' } }
```

⇒ 流结束时若无 finish 块，DSH **默认判为 `stop`（即成功）**。即文章「unknown → 拒绝当成功」这一条，**DSH 也未遵循**。

### 2.2 G2「预算闸缺失」—— DSH 同样没有

原报告 G2 称「只有步数闸、无 Budget 闸」为「生产事故级缺口」。**DSH 同样没有预算闸**：

| 证据 | 内容 |
|---|---|
| `[DSH]` `packages/` 全库 grep `costBudget｜budgetUsd｜maxCost｜tokenBudget｜haltBudget` | 唯一命中是 `thinkingTokenBudget`（`llm/llm-pi-ai/src/catalog.ts`），是**模型推理参数**（思考 token 上限），**不是成本闸** |
| `[DSH]` `packages/guard/` 目录 | 只有两个包：`repeat-tool-reminder` 与 `timeout-policy` |
| `[DSH]` `packages/guard/repeat-tool-reminder/src/index.ts:2-5,53` | 头注释即写明「**enriches post-execute decisions … without vetoing or rewriting calls**」——**advisory，只提醒不否决**；默认阈值 `thresholds: z.array(z.number()).default([3, 5, 8])` |
| `[DSH]` `packages/guard/timeout-policy/src/index.ts:2,25` | 单工具级超时（工具自声明 `timeoutMs`，映射为 `TOOL_TIMEOUT`），**不是** run/turn 级预算 |

⇒ 「无 Budget 闸」**不是落后于 DSH，而是两者都没有** —— 它是外部文章的**理想项**，若要实现属**自研增强**，不应以「对齐 DSH」的名义立项。

### 2.3 G2 的姊妹问题 —— DSH 连 MaxSteps 都没有

原报告把「只有 MaxSteps」记为「🟡 部分达标」。按 DSH，这个「部分」需要重新表述：

| 证据 | 内容 |
|---|---|
| `[DSH]` `packages/core/agent-loop/src/agent.ts:315` | 外层 turn 循环是 `while (true)`（内层 `agent.ts:409` 亦为 `while (true)`，是 step 重试） |
