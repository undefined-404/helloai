## §0 定位与边界（★先读）

### ① 问题来源

- 「星际弹幕 Three.js 小游戏开发与完整验收交付」任务平台无运行时核验能力，最终人工审核通过。
- 平台 review 改造（RV-1~7 / SR-1~5）已覆盖文本与元数据判定，但没有浏览器 / 渲染 / 视觉证据面。
- 用户要求把调研结论中的 10 个待核问题整理成可执行清单，供次日逐项核对。

### ② 本清单做什么

- 把「运行时 UI 验收」落地前必须确认的 10 个事实，逐项写成：**核对动作 / 通过判据 / 证据回填**。
- 产出结论：平台是否具备最小可行性（视觉模型、MCP 图片、沙箱 WebGL、截图存储、验收类型链路）。
- 为后续 `design/` 或 `plan/` 提供事实依据，而不是直接进入实现。

### ③ 本清单不做什么

- **不实现**浏览器工具、`RUNTIME_UI` 验收或 VLM reviewer——本清单只核事实。
- **不选型拍板**（Playwright MCP vs 原生工具、VLM 供应商）；只记录可行性与约束，选型另立设计。
- **不改代码 / 数据库 / 配置**；如需临时验证，只在沙箱或本地测试夹具中执行。
- **不写排期与人力**；完成时间由使用者自行决定。

### ④ 诚实边界

- 10 项全部通过，也只证明「**平台有能力做运行时验收**」，不证明「游戏质量可自动判定」；L4「好玩 / 手感 / 美术」仍归人工。
- 视觉指标、像素 diff、FPS 都可能误判；本清单只核「能否拿到证据」，不核「证据阈值是否合理」。
- 安全与成本可能直接否决方案（例如沙箱无法跑 WebGL、图片 token 成本过高）；结论必须如实记录，不得为了推进而忽略。
- 核对结论是**时间点事实**；依赖的模型 / 沙箱 / 框架版本变化后需重核。

## §1 核对项（RUI-1 ~ RUI-10）

### A. 模型与多模态

#### RUI-1 内部 model 路由是否支持图片输入？

> **状态**：待开始 ｜ **剩余动作**：核对 provider / model 能力与真实调用

- [ ] 查 `llm_provider_model` 的 `capabilities`（输入模态 / vision / image）与 provider catalog 的模型能力声明。
- [ ] 查 reviewer 可选模型清单，确认至少一条路由声明支持图片。
- [ ] 用一张最小 PNG 做真实调用（或在测试环境 mock 路由），确认模型能收到 image block。
- **通过判据**：至少 1 条 reviewer 路由可接收图片；不支持时能明确降级为「不看图」而不是静默丢图。
- **证据回填**：模型名 / 路由 / capabilities 原始值 / 调用结果截图或日志。

#### RUI-2 Spring AI / HelloAI 的 MCP 客户端能否把图片结果传给模型？

> **状态**：待开始 ｜ **剩余动作**：核对 MCP 工具结果的 image block 投影链路

- [ ] 查 `McpToolConfig`、`RuntimeTurnExecutor`、`InternalToolCallbacks` 的工具结果投影。
- [ ] 确认 MCP 工具返回的 image block 是否被保留为多模态消息，而不是转成文本 / 丢弃。
- [ ] 若当前不支持，记录需要改的投影点与影响面（不要在本清单里实现）。
- **通过判据**：截图类工具结果能进入模型消息；失败/不支持时有明确诊断。
- **证据回填**：链路文件 / 行号 / 一次假 MCP 结果的投影结果。

#### RUI-3 reviewer Prompt 如何注入图片？是否需要独立 VLM reviewer？

> **状态**：待开始 ｜ **剩余动作**：核对 Prompt 渲染与模型路由的图片承载方式

- [ ] 查 `prompts/subtask-review.md`、`ReviewEvidenceView`、`ReviewExecutionEngine.renderPrompt` 的证据装配。
- [ ] 确认 reviewer 是「同一模型收图」还是「单独 VLM reviewer agent」；记录两种方式的成本 / 权限 / 失败降级。
- [ ] 明确无视觉路由时的口径：不得判视觉类通过，应转人工或 `INCONCLUSIVE`。
- **通过判据**：截图能进 reviewer；无视觉能力时行为显式且不假通过。
- **证据回填**：选定方式 / Prompt 占位符 / 降级口径。

### B. 沙箱与浏览器

#### RUI-4 OpenSandbox 能否运行 Chromium 与 WebGL？

> **状态**：待开始 ｜ **剩余动作**：在沙箱内做最小渲染验证

- [ ] 确认沙箱镜像是否能安装 / 启动 Chromium（headless）。
- [ ] 用最小 WebGL 检测页验证 `canvas.getContext('webgl2')` / `webgl` 非空（SwiftShader / EGL）。
- [ ] 验证截图、30s 稳定性、CPU / 内存 / 时长上限。
- **通过判据**：canvas 与 WebGL context 非空；截图成功；30s 不崩；资源受限可观测。
- **证据回填**：镜像 / 启动命令 / WebGL 结果 / 截图 / 资源数据。

#### RUI-5 选 Playwright MCP 还是原生 `internal_browser_*`？

> **状态**：待开始 ｜ **剩余动作**：对照两种路径的集成成本与可控性

- [ ] 对照 MCP 工具发现、会话归属、截图附件、权限 / 出网、Spring AI 兼容性。
- [ ] 对照原生工具的动作集（navigate / dom_tree / click / type / key / screenshot / eval_js / tabs）。
- [ ] 记录两种方式对内部 LLM / reviewer 的可见性与测试方式。
- **通过判据**：选定一条可被内部 LLM 调用、截图可入库、失败可观测的路径（选型可在本项记录倾向，不在此拍板）。
- **证据回填**：对比表 / PoC 结果 / 未决风险。

#### RUI-6 浏览器沙箱的安全边界是否足够？

> **状态**：待开始 ｜ **剩余动作**：验证出网、`file://`、密钥与资源隔离

- [ ] 验证出网白名单 / 私网拦截；不可信页面不能访问本机 / 内网 / 平台服务。
- [ ] 验证 `file://` 被禁用（WebArena 曾有 `file://` 读参考答案的漏洞）。
- [ ] 验证沙箱内看不到平台密钥 / 数据库凭据；CPU / 内存 / 时长 / 磁盘有上限。
- **通过判据**：不可信页面无法越界；失败时明确报错，不静默放行。
- **证据回填**：攻击用例 / 拦截结果 / 资源上限配置。

### C. 验收与存储

#### RUI-7 新增 `AcceptanceKind.RUNTIME_UI` 要改哪些链路？

> **状态**：待开始 ｜ **剩余动作**：盘点枚举 / DB 约束 / 提示词 / 前端

- [ ] 查 `AcceptanceKind`、DB `chk_sub_task_acceptance_kind`、`AcceptanceKindValidator`。
- [ ] 查拆解提示词（decompose / expand / regenerate）与验收判据文档。
- [ ] 查前端标签 / 筛选 / 详情渲染；确认旧数据兼容。
- **通过判据**：列出完整改动面；新增值不会让旧数据 / 旧链路失效。
- **证据回填**：文件 / 行号 / 迁移需求 / 兼容性结论。

#### RUI-8 截图 / 录屏存哪里、保留多久？

> **状态**：待开始 ｜ **剩余动作**：核对附件存储与快照体积策略

- [ ] 查 attachment / MinIO 现有存储、大小上限、保留策略。
- [ ] 核对 RV-6 冻结快照 `300000` 字符上限与图片 / 视频二进制的关系（引用还是复制）。
- [ ] 明确截图 / 录屏是否进 reviewer Prompt、是否进冻结证据、是否长期保留。
- **通过判据**：有明确存储路径、上限、保留期；不撑爆 `review_record`；复判可引用。
- **证据回填**：存储方案 / 上限 / 清理策略 / 快照引用方式。

### D. 成本与测试

#### RUI-9 运行时验收的成本是否可接受？

> **状态**：待开始 ｜ **剩余动作**：估算单次 L1~L3 验收成本

- [ ] 估算截图 image token / VLM 评审 token、浏览器启动时间、录屏存储。
- [ ] 对比现有纯文本 review 的单次成本。
- [ ] 给出阈值：超过多少成本 / 时长时降级为「只做 L0-L1 + 人工」。
- **通过判据**：有可接受上限与降级策略；不是「先做再说」。
- **证据回填**：成本表 / 假设 / 降级阈值。

#### RUI-10 测试策略：fake browser + 真实 e2e 怎么分层？

> **状态**：待开始 ｜ **剩余动作**：确认单测与 e2e 边界

- [ ] 参考 Octop 的 fake `browser_tool` 单测模式：单测不依赖 Chrome。
- [ ] 参考 DSH Stagehand 的安装浏览器 e2e lane：真实 Chromium 测试用环境变量开关。
- [ ] 确认 CI 是否具备 Chromium / WebGL；无则记录 e2e 仅本地执行。
- **通过判据**：单测 hermetic；e2e 可重复；CI 边界明确。
- **证据回填**：测试分层 / 环境变量 / CI 限制。
