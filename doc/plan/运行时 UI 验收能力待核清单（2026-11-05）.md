## §0 定位与边界（★先读）

### ① 问题来源

- 「星际弹幕 Three.js 小游戏开发与完整验收交付」任务平台无运行时核验能力，最终人工审核通过。
- 平台 review 改造（RV-1~7 / SR-1~5）已覆盖文本与元数据判定，但没有浏览器 / 渲染 / 视觉证据面。
- 用户要求把调研结论中的 10 个待核问题整理成可执行清单，供次日逐项核对。

### ② 本清单做什么

- 把「运行时 UI 验收」落地前必须确认的 10 个事实，逐项写成：**核对动作 / 通过判据 / 证据回填**。
- 产出结论：平台是否具备最小可行性（视觉模型、MCP 图片、沙箱 WebGL、截图存储、验收类型链路）。
- 为后续 `design/` 或 `plan/` 提供事实依据，而不是直接进入实现。

### ③ 本清单不做什么

- **不实现**浏览器工具、`RUNTIME_UI` 验收或 VLM reviewer——本清单只核事实。
- **不选型拍板**（Playwright MCP vs 原生工具、VLM 供应商）；只记录可行性与约束，选型另立设计。
- **不改代码 / 数据库 / 配置**；如需临时验证，只在沙箱或本地测试夹具中执行。
- **不写排期与人力**；完成时间由使用者自行决定。

### ④ 诚实边界

- 10 项全部通过，也只证明「**平台有能力做运行时验收**」，不证明「游戏质量可自动判定」；L4「好玩 / 手感 / 美术」仍归人工。
- 视觉指标、像素 diff、FPS 都可能误判；本清单只核「能否拿到证据」，不核「证据阈值是否合理」。
- 安全与成本可能直接否决方案（例如沙箱无法跑 WebGL、图片 token 成本过高）；结论必须如实记录，不得为了推进而忽略。
- 核对结论是**时间点事实**；依赖的模型 / 沙箱 / 框架版本变化后需重核。

## §1 核对项（RUI-1 ~ RUI-10）

### A. 模型与多模态

#### RUI-1 内部 model 路由是否支持图片输入？

> **状态**：**已有结论（2026-11-25）**——**通过**（对话面 + 执行面两条链四模型对照实测）
>
> **结论**：至少 1 条 reviewer 路由可接收图片（实测 3 条）；不支持时能明确降级而非静默丢图。**通过判据成立。**

- [x] 查 `llm_provider_model` 的 `capabilities`（输入模态 / vision / image）与 provider catalog 的模型能力声明。
- [x] 查 reviewer 可选模型清单，确认至少一条路由声明支持图片。
- [x] 用一张最小 PNG 做真实调用（或在测试环境 mock 路由），确认模型能收到 image block。
- **通过判据**：至少 1 条 reviewer 路由可接收图片；不支持时能明确降级为「不看图」而不是静默丢图。
- **证据回填**：

**★口径订正（重要，勿再误读）**：本清单初版把「查 `capabilities` 声明」当作能力依据。实测证明该列在本系统里的语义是**「经本平台此 provider 实际可达的输入模态」**，而非「模型官方声明的能力」。两者会分叉——`deepseek` 官方文档标注图像理解「支持」，但本平台经 `spring-ai-deepseek` 专用 SDK 根本送不到图（`DeepSeekChatModel#createRequest` 无 media 分支），故已按 fail-close 声明为 `["text"]`（`V155`）。**判据只能靠「模型答对 / 答错」的对照实验，不能靠查表。**

**实测方法**：素材为「答案只存在于图中」的图（白底居中 6 位随机数字，图与答案 sidecar 同批生成），同一句提问，**带图轮 vs 不带图轮**各跑一遍；带图轮须答出图中数字、不带图轮须回 `NO_IMAGE` 否则基线无效。

| 模型 | 对话面（`assistant/streamCreate`） | 执行面（隔离任务版） | 判定 |
|---|---|---|---|
| `minimax:MiniMax-M3` | 答对 `530872` | 答对 `518436` | 可收图 |
| `dashscope:qwen3.7-plus` / `qwen3.8-flash` | 答对 `530872` | 答对 `378297` | 可收图 |
| `moonshot:kimi-k3` | `530972`（8→9） | `728920`（8→9，正确答案 `728820`） | 可收图，**OCR 误差**（直连官方接口同错，非平台缺陷） |
| `deepseek:deepseek-flash` | 「无法查看图片内容」 | 报告 `BLOCKED`，明确「不能凭空推测数字，以免伪造交付物」 | **通道失效 → 已 fail-close 声明 text-only** |

**关键旁证**：①无图基线四模型**全部**回 `NO_IMAGE` ⇒ 带图轮答对只能来自像素；②泄漏自检：带图轮 prompt 里无「已完成子任务」段、不含任何模型答案串 ⇒ 排除跨子任务答案泄漏；③`deepseek` 反证 —— 同 key 直连 `api.deepseek.com` 发 `image_url` 返 200 且正确读出 `530872` ⇒ 根因在 SDK 而非 provider。

**证据落点**：`plan/HelloAI 视觉验收与沙箱浏览器实施计划（2026-11-24）.md` 的 `VU-8` 章节「对照实验（2026-11-25）」两段（对话面 / 执行面），两处同源、不各写一份；DB 侧处置见 `V155` 迁移头部。

**仍未覆盖**：reviewer 侧（`VU-2` 未落地，`ReviewExecutionEngine` 的 `AgentTask` 构造处无 `.mediaRefs`、`EvidenceContent` 仍只有 3 分量）。实测副作用：`minimax` 的自动评审被驳回，理由正是「原始图片未出现在审核附件中，无法独立核验 OCR 结果」——这印证了 reviewer 缺图是真实缺口，不是实验瑕疵。

#### RUI-3 reviewer Prompt 如何注入图片？是否需要独立 VLM reviewer？

> **状态**：**已有结论（2026-11-25）｜部分通过**——**结构性答案已定（不需要独立 VLM reviewer），但注入通道未建**
>
> **结论**：选「reviewer 与执行器同一模型收图」路线，**不新建独立 VLM reviewer agent**（理由见下）。但**该通道当前完全未建**：`ReviewExecutionEngine.runOnce` 构建 `AgentTask` 处未填 `.mediaRefs`、`EvidenceContent` 只有 3 分量、`ReviewEvidenceAssembler.buildMediaVisibilityNote` 仍为「看不到 → 从严核」的反向文案、prompt 无媒体占位符。⇒ `RUI-3` **通过判据不成立**（截图不能进 reviewer），但「选哪种方式」这个问题已有确定答案，`VU-2` 不必再做技术选型。

- [x] 查 `prompts/subtask-review.md`、`ReviewEvidenceView`、`ReviewExecutionEngine.renderPrompt` 的证据装配。
- [x] 确认 reviewer 是「同一模型收图」还是「单独 VLM reviewer agent」；记录两种方式的成本 / 权限 / 失败降级。
- [x] 明确无视觉路由时的口径：不得判视觉类通过，应转人工或 `INCONCLUSIVE`。
- **通过判据**：截图能进 reviewer；无视觉能力时行为显式且不假通过。
- **证据回填**：

**为什么选「同一模型收图」而不是独立 VLM reviewer**：①两者都需要「图进 prompt」这一步，独立 VLM 只是把同一步搬到另一个 agent，通道成本不减而多一个跨 agent 身份与凭证面；②本项目已有 `ImageInputCapabilityPolicy` 唯一判定（`VU-10`），同一模型路线可直接复用，独立 VLM 路线会引出「两个模型能力位分别声明」的第二事实源（判据 4）；③失败降级语义更简单——同一个模型要么能看要么明说看不到，不需要「VLM 看完了再喂给文本 reviewer」这层转写损失。

**当前实测到的两个事实（值得记，否则会反复误判）**：
1. **「无视觉时只说从严核」在实测中不够**：`minimax` 子任务正确读出图中数字，却被自动评审**驳回**，理由是「原始图片未出现在审核附件中，无法独立核验 OCR 结果」；同批 `qwen` 则拿到 `score=4` 放行。同一个缺陷在两条链上表现不同 ⇒ 「仅靠文案从严」会产生**假驳回与假放行并存**，不能作为长期方案。
2. **视觉类交付物在 reviewer 侧的现状是「只能靠格式合规兜底」**：reviewer 拿不到图，只能核「是否给出 6 位数字」这种形式判据，核不了「数字对不对」。

**降级口径（现在就写死，`VU-2` 按此实现）**：reviewer 未拿到图时，对**视觉类交付物**不得判通过——须 `INCONCLUSIVE` 或转人工，且理由须显式写出「本评审未收到原始图片」。**禁止**用「格式看起来合规」代替视觉核验后放行（那正是上面 `qwen score=4` 的假放行路径）。

**待办归属**：全部归 `VU-2`（填 `mediaRefs` + `EvidenceContent` 加第 4 分量 + 反转 `buildMediaVisibilityNote` + prompt 占位符），本清单不实现。
