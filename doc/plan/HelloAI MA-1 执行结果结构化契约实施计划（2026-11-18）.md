### ② 本计划做什么

**一句话目标**：给「执行结果」立一份**稳定的公开读取契约**，让任何客户端拿到的是**已声明格式的数据**，而不是一段需要猜的文本。

五条具体产出（逐条对应 §3 任务表）：

1. 新增只读端点 `GET /api/sub-tasks/getExecutionResultById/{id}`，返回 `{ format, markdown \| parts, sections, truncated }`；
2. 该端点**只做「选择 + 打包」**：`format` 二选一、`markdown` 直取已冻结的 `output`、`parts` 保原序；
3. 剥离尾部 `## EXECUTION_RECORD` 机器块，起止标记收敛为**唯一常量**，与回填侧共用；
4. 前端 `SubTaskDetail.vue` 由「正则猜结构」切换为「按 `format` 选渲染器」，`StructuredTextView` 退为历史数据兜底；
5. `sub_task.context` 定性为「内部状态，客户端不得依赖」，并在 DTO 上标注 + 登记待迁三项。

### ③ 本计划不做什么

| 不做 | 为什么 | 依据 |
|---|---|---|
| **不删 `projectToText` / 不删 `output`** | `output` 有 6 个消费方，其中 `AgentRuntimeContextAssembler.loadUpstreamContent`（下游子任务读上游产出）与 `McpReadModelServiceImpl`（外部 Agent 读上游产出）是 LLM 上下文，删了会立刻让下游读不到成果 | 蓝图 §4 `MA-1` ③ 消费方表；判据「删投影前先分清机器事实与呈现投影」 |
| **不实现 `sections[]`** | 现在只有 Web 一个消费方，实现它就是给一个没有读方的字段写解析器 | 判据 2（无读取方的列 = 反模式） |
| **不改写侧**（`ExecutionResultHandler` 的落库形状） | 本次只补读取方。写侧一改，`lastExecution` 的老数据形状与解析逻辑要同时动，回归面扩大数倍 | 协作规约 §2.1 最小改动 |
| **不改 `conversation_message.content`** | 对话流是另一条通道，它承载多轮历史；改它等于同时改渲染与历史数据结构 | 蓝图 §4 `MA-1` ⑦ 问题 3（历史轮次列为已知边界） |
| **不做 `file` 分片的物化** | `submitResult` 的 `file` 分片当前显式拒收（400），本批只保留渲染分支空位 | `ADR-009` A 档实施记录；蓝图 `MA-1` ⑤ |
| **不删 `structuredText.ts` / `StructuredTextView.vue`** | 老数据（`format` 缺失）与历史轮次仍要走它兜底，删了会白屏 | 蓝图 §4 `MA-1` ⑦ 问题 4 |

### ④ 诚实边界

**落地后仍有以下不成立，必须同步登记差距表**：

1. **历史轮次仍是纯文本**。`lastExecution` 只保存最后一轮；返工多轮的旧产出在 `conversation_message` 里，翻历史看到的是未结构化的文本。**这不是缺陷，是本期刻意不覆盖的范围**。
2. **`context` 的「客户端不应依赖」是软约束，不是机制**。字段仍然整包下发，前端仍有若干处在读它。本计划只做「标注 + 登记待迁」，**没有任何代码强制客户端不读**。移动端开工前不构成已收口。
3. **`sections` 是空位不是能力**。字段恒 `null`，任何客户端不得据此判断"支持分块渲染"。
4. **小程序渲染仍依赖第三方 Markdown 组件**。本期下发的是 `format:"markdown"` 的**数据**，小程序侧要自己接 `towxml` 一类库；「一次编写多端一致」要等 `sections` 真正实现才成立。
5. **`parts` 的 `data` 分片语义未收敛**。契约只规定它是字符串，不规定内部 schema；前端按 JSON 尝试解析、失败降级文本。**这等于承认"结构化"只到分片这一层，不保证业务结构**。

## 4. 关键设计决策

| 决策 | 选了什么 | 为什么不选另一种 |
|---|---|---|
| 读模型形态 | **「选择 + 打包」**：`format` 决定用哪份既有事实 | 「读时按 `parts` 重算文本」会让读时结果与写时冻结的 `output` 随规则变更而分叉（判据 4） |
| 端点位置 | **独立端点**，不塞 `SubTaskResponse` | `SubTaskResponse` 被列表接口共用（`/list` 分页、`listAvailable`、`listMine` 全走同一 mapper），而 `parts` 单行上界约 1.28M 字符（`MAX_PARTS=20 × 64k`）⇒ 塞进去等于列表页无条件拖大 JSON |
| 下发形态 | **数据**（`{format, markdown \| parts}`），不下发 HTML | 小程序没有 `v-html`，下发 HTML 等于把 Web 的技术选型锁成平台契约 |
| `sections` | **预留字段，恒 `null`** | 现在实现等于给一个没有读方的字段写解析器（判据 2）；但字段不预留，将来加它就是破坏性变更 |
| `EXECUTION_RECORD` 剥离 | 在**读模型侧**剥，不在写侧剥 | 写侧 `output` 要保留尾部块供回填；剥了 `parseAndAppendExecutionRecord` 就解析不到 |
| `parts` 元素 DTO | 复用 core 的 `ExecutionPart` | api 域自建一份平行 DTO = 同一事实双写，字段一改就漂 |
| `context` | 标注为「客户端不得依赖」，**不删** | 内部链（`loadUpstreamContent`）与 Agent 通道（`McpReadModelServiceImpl`）仍在读；删了是断链 |

### 4.1 已识别的最高危漏项（实现时逐条对照）

| # | 问题 | 本计划如何覆盖 |
|---|---|---|
| 1 | **内部 LLM 不产 `parts`** ⇒ 只做 `parts` 分支等于白做 | `MA1-3` 的 `format` 二选一规则保证内部链走 `markdown` 分支；`MA1-8` 必须验「内部 LLM 子任务按 Markdown 渲染」 |
| 2 | **尾部 `EXECUTION_RECORD` 会露在页面上** | `MA1-1` 常量 + `MA1-3` 剥离；验收项「详情页任何位置看不到 `## EXECUTION_RECORD`」 |
| 3 | **老数据 / 老后端无该字段** | `MA1-6` 类型可选 + `MA1-8` 三路判断 + 请求失败静默回落 |
| 4 | **`data` 分片非合法 JSON** | `MA1-7` try/parse 失败降级，不报错不空白 |
| 5 | **XSS** | `MA1-7` 禁 `v-html`；`MA1-8` 的 Markdown 走既有 `html:false` + `DOMPurify` |

## 5. 依赖与实施次序

```text
MA1-1（常量收口，无依赖，先做）
  └─→ MA1-2 → MA1-3 → MA1-4 → MA1-5     后端闭环，可独立验收
                              └─→ MA1-6 → MA1-7 → MA1-8    前端闭环
                                                    └─→ MA1-9（纯文档，可随时插）
```

- **`MA1-1` 必须最先**：`MA1-3` 依赖它的剥离函数；不先收口常量，剥离规则会与回填侧各写一遍。
- **`MA1-4` 完成后即可用 curl 验收后端**，不必等前端 —— 这样前端出问题时能立刻分清是契约错还是渲染错。
- **`MA1-9` 与代码无依赖**，可随时插入。

### 5.1 停止条件（本计划在哪停是安全的）

| 停在哪 | 安全吗 | 判定口径 |
|---|---|---|
| `MA1-4` 完成（后端端点通） | **不安全** | 又一个「只写不读」——正好是本计划要消灭的那个反模式 |
| `MA1-8` 完成（前端切换） | **安全，且是干净停点** | 用户在详情页能看到两种呈现，`parts` 有了真实读取方 |
| `MA1-9` 未做 | 安全 | 它是标注与登记，不影响功能；但**移动端开工前必须补**，否则 `context` 会被当契约 |

## 6. 验收

逐条可独立执行，不依赖其他 `MA` 项。

| # | 场景 | 期望 |
|---|---|---|
| 1 | 外部 Agent 提交 `text` + `data` 两分片 | 端点返回 `format:"parts"`；详情页两种不同呈现（文本流 + 可展开 JSON，顺序与提交一致） |
| 2 | 内部 LLM 子任务 | 端点返回 `format:"markdown"`；详情页按 Markdown 渲染（标题 / 列表 / 代码块 / 表格正常） |
| 3 | 无 `parts` 的老数据 | 端点返回 `format:"markdown"`；正文与改造前是**同一份 `output`**（剥掉回填块后），呈现由「结构猜测」改为 Markdown 渲染；对话流最后一条执行产出默认收起，同页不出现两份正文 |
| 4 | 任意一次执行结果 | 详情页任何位置**看不到** `## EXECUTION_RECORD` 文本（含对话流 `sub_task_execute` 消息） |
| 5 | `data` 为非法 JSON | 降级纯文本，不报错、不空白 |
| 6 | 列表接口 `/list` | 响应体大小与改造前一致（新读模型不出现在列表路径） |
| 7 | 深色主题 + 窄屏（<480px） | 两种呈现均可读；`data` 默认折叠 |
