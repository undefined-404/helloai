## 0. 定位与边界（★先读）

### ① 问题来源

- **人侧无消息载体**：`agent_inbox` 收件人是 `agent_id`（机器通道），人这一侧无对等对象;全仓 `user_notification` / `announcement` **0 命中**（`[实测]` 2026-11-12，无实体、无迁移、无前端封装）。
- **`DEAD_LETTER` 零通知**：`SubTaskNotificationServiceImpl.sendInboxNotification` 的 `switch` 只覆盖五态，`DEAD_LETTER` 走 `default -> {}`（[SubTaskNotificationServiceImpl.java:140-153](file:///E:/yhzx/1027/helloai/helloai-core/src/main/java/com/helloai/core/task/service/impl/SubTaskNotificationServiceImpl.java#L140-L153)）——最需人立刻知道的一件事反而无通知。
- **异步长任务无提醒（空头承诺）**：拆解/派生/报告整合都是异步长任务，`PlanReviewDialog.vue:199-200` 已对用户写明「产出后站内提醒」，后端无实现（[PlanReviewDialog.vue:195-203](file:///E:/yhzx/1027/helloai/helloai-ui/src/views/task/components/PlanReviewDialog.vue#L195-L203)）。
- **公告无载体**：`sys_config` 是键值表，无历史版本、无按用户已读位，承载不了「打开项目第一时间看到最近更新了什么」。
- **无平台级启用开关**：用户要求消息与公告都可在平台配置控制启用，默认关闭，启用后才在工作台可见。

### ② 本计划做什么

1. **单一出口 + 映射注册表**（`MSG-1`）：`NotificationService.publish(NotificationEvent)` 唯一入口;`NotificationType` 枚举（首批 17 值）+ `Severity` + 事件码→消息白名单映射（`ONCE`/`BUCKET`/`SILENT` 三形态）。业务侧只上报事实，文案/深链由消息域集中渲染。
2. **消息表 + 幂等**（`MSG-2`）：`V151` `user_notification` + `COALESCE(receiver_id,0)` 唯一索引（NULL 广播陷阱）+ 未读局部索引;实体（`PgJsonbTypeHandler`）+ Mapper。
3. **钩子接线 + SSE**（`MSG-3`）：`TaskTimelineServiceImpl.recordEvent` 写点后挂钩子（`recordEventInNewTx` 委托之、一处覆盖两入口）;ownerId 在 task 域解析后传入;`NotificationCreatedEvent` + `NotificationEventHub`（`AFTER_COMMIT`，帧体仅 notificationId）。
4. **首批映射登记**（`MSG-4`）：A1 草案就绪 / A3 报告完成 / A5 Agent 提交（内外共用）/ B1 死信（URGENT）/ B2 无候选（HIGH，BUCKET 1h）;同批兑现 `PlanReviewDialog.vue:199-200` 承诺。
5. **前端消息侧**（`MSG-5`）：`stores/notification.ts` + `api/notification.ts` + `api/notificationStream.ts` + 铃铛 + 抽屉 + MainLayout 挂载 + 工作台红框最小入口 + Settings 两开关 + `features` 端点。
6. **置顶公告**（`MSG-6`，本次纳入）：合并 `V151` 内的公告三表 + RBAC（`notice:view`/`notice:edit` + 菜单）+ `AnnouncementService`（草稿/发布 version+1+revision/归档/历史/版本已读）+ 管理页 + 顶部公告条（折叠记忆）。
7. **两个平台开关**（贯穿 `MSG-1`/`MSG-5`/`MSG-6`）：`notification.enabled` / `announcement.enabled`，默认 OFF，停发 + 隐藏（§3.10 设计）。
8. **验证收口**（`MSG-8`）：编译/门禁/架构守卫 + 单测/集成 + 真机可见性 + 多副本幂等 + 开关 OFF 停发隐藏 + 文档回填。

### ③ 本计划不做什么

1. **不做 `MSG-7` 扩展覆盖**：A2/A4/B3~B7/C1~C5 + 外部 Agent 上线（例外通道）+ `task_timeline`↔`user_notification` 对账 SQL + B4 `RESTRUCTURING` 事件码回源，列后续阶段。**依据**：用户裁定交付范围 = 首批 + 公告。
2. **不做站外渠道**：邮件 / IM webhook / 短信未接入;`Settings.vue:797` 硬编码 `['web']` 订阅偏好空壳不接管。**依据**：设计 §4 边界 2。
3. **不做逐类订阅偏好 / 移动推送 / @提及 / 私信 / 消息内直接操作**。**依据**：设计不含项。
4. **不做历史回填**：消息从钩子上线那一刻起才有，OFF 期间事件永久不补发。**依据**：设计 §4 边界 3 + 用户「停发 + 隐藏」口径。
5. **不做多条置顶**：`pinned` 单条语义，顶部条只渲染一条。**依据**：设计 §3.7。
6. **不为消息建状态机**：只有未读/已读/归档三态布尔位组合，有效性判深链回源。**依据**：设计 §3.4 + `doc/log/README.md` §10.5「状态不重复建模」。
7. **不做跨副本实时**：SSE 单进程，多副本靠未读列表补齐数据、不保证时机;不引 Redis pub/sub。**依据**：设计 §4 边界 1。
8. **不改 `agent_inbox` 机器通道与 `WorkbenchEventHub` 既有 SSE**：方向相反（平台→Agent vs 平台→人），不共表、不迁移。**依据**：设计 §3.1。
9. **不映射 `task_cancelled`**：该码经 `TaskServiceImpl.changeStatus` 直插、绕过 `recordEvent`（[TaskServiceImpl.java:246-251](file:///E:/yhzx/1027/helloai/helloai-core/src/main/java/com/helloai/core/task/service/impl/TaskServiceImpl.java#L246-L251)），首批不映射故无损失;登记为已知边界。**依据**：设计 §3.3 / §4 边界 8。

### ④ 诚实边界

- **system 不可依赖 task**（域链 planner > review > task > knowledge > agent > system > event > dlx > shared）：ownerId **必须在 task 域钩子内**用 `TaskMapper.selectById(taskId).getOwnerId()` 解析后传入 `publish`;消息域不注入 task 任何类。用 `TaskMapper`（非 `TaskService`）避免服务环——`[实测]` `TaskServiceImpl` 只注入 `TaskTimelineMapper`，无环。
- **`recordEvent` 不去重**（类注释明写「重写是 OK 的」）：借时间线行 id 做键 ⇒ 时间线重复写几条、消息就发几条。处置在映射表按码显式标形态（重试类标 `BUCKET`），不在消息层猜。
- **COALESCE 不是装饰**：Postgres 唯一索引把 NULL 视为互不相等，广播消息（`receiver_id IS NULL`）走普通唯一索引根本不去重。必须 `COALESCE(receiver_id,0)` 并在单测锁定。
- **URGENT 写失败偏离 best-effort**：机器通道全局 best-effort（失败只 warn）;人侧 `URGENT`（B1 死信）写失败必须 **error 级留痕**，不得只 warn 而过。新代码注释须写明依据设计 §3.6。对账 SQL 归 `MSG-7`。
- **开关默认 OFF 靠键缺省**：不写 `sys_config` 种子;读取镜像 `isRegisterEnabled()`（`"1"/"true"`），**禁用** `QuotaWidgetSettings.isWidgetEnabled()` 的 `!"0"` fail-open（默认 ON 会让未配置时意外可见）。
- **公告写入不受开关限制**：管理员可在 OFF 时预写/发布草稿，OFF 只隐藏读取与展示;`publish` 停发只约束事件消息。
- **迁移水位以实查为准**：`[实测]` 磁盘最大 `V150`，`V151` 空闲;`validate-on-migrate=false`（[application.yml:89](file:///E:/yhzx/1027/helloai/helloai-start/src/main/resources/application.yml#L89)）不拦混合 schema，立项时已重查。项目记忆中 `V151`/`V152`/`V155` 为过期登记。
- **三迁移合并为一个小版本**：〔2026-11-15 用户裁定「数据库版本 151-153 合并成一个，依次 plan 任务是一个小版本」〕原 `V151` 消息表 / `V152` 公告三表 / `V153` RBAC 合并为单一 `V151__notification_announcement.sql`（§1 消息 / §2 公告 / §3 RBAC），覆盖「一份迁移只做一件事」纪律;`V152`/`V153` 号段释放（`V153` 仍留给后续 AD-5a 存量草案迁入）。合并前两侧库均 `V150` 水位、三文件未提交未应用，重组不触发 checksum;合并后 10 集成用例 Testcontainers 全绿（详见设计 §6 第三次条目）。
- **本计划完成不关闭 `MSG-7`**：扩展覆盖与对账 SQL 仍是独立后续;`G-035` 只覆盖首批 + 公告 + 开关本身。
