## 0. 定位与边界（★先读）

**① 问题来源**

- **用户裁定（2026-11-04）**：review 应拆为**他审（reviewer）**与**自审（self-review）**两条业务，两处都要调整（原文见文档头）。
- **外部机制对照**：`security-audit-skill`（Cloudflare，MIT）在「证明审全了」上比本项目走得更远——覆盖台账 / 三态裁决 / 确定性 validator / 对立面复核，四项均已代码化；两份独立分析主要结论一致（一份看全局流程，一份看单点判定），其中 3 处细节经代码复核订正（见 §2）。仅借机制，不复制领域内容（安全领域知识库不适用）。
- **代码级根因**（详见 §2）：review 判定从「提示词有约束」到「代码有强制」之间是**空的**——`analysis` / `acceptanceRef` / `nit` vs `blocker` 三条提示词要求都没有对应校验（§2.1 事实 5~7）；自审轮则被**显式关掉工具**（§2.2 事实 12~13），所谓「自审」只是模型自述。
- **差距表锚点**：`G-007`（Rule + Test + LLM 统一决策，状态「待开始」）；正交相邻项 `G-016`（技能注入契约，已关闭）。
- **观测缺口**：抽检只抽 `APPROVED`，驳回侧无独立复核（§2.1 事实 9），「误伤率」不可度量。

**② 本计划做什么**

把「审没审全」「自审跑没跑」从**口径问题**变成**机读事实**。具体产出六条：

1. **`RV-1` 纯静态判定校验器**：`analysis` 非空 / `acceptanceRef` 子串归属 / `pass`↔`score` 双向一致 / 宽松解析标记，全部确定性、零 token。
2. **`RV-2` 三态结论**：`APPROVED / REJECTED / INCONCLUSIVE`，让「证据不足」不再被迫二选一（放行或返工），并与抽检表 `review_recheck_log` 同步放宽约束。
3. **`RV-3` `coverage[]` 结构化 + 静态覆盖批评器**：验收点逐条状态机读，覆盖判据改为 **`criterionRef` 子串归属**（不用「条数相等」，见 §4 决策 D2）。
4. **`RV-4` 抽检独立性**：排除原判定人；LLM 失败/超时补 timeline 事件，与 `UNPARSEABLE` 区分。
5. **`SR-1` ~ `SR-4` 自审走沙箱**：收尾轮放开**仅一个**受限工具、围栏升级为可机读 `EVIDENCE`、闸门只判「证据是否存在且一致」、不合格同 turn 有界重跑、沙箱不可用显式降级。
6. **`SR-5` 沙箱调用台账**（本轮新增）：`OpenSandboxExecutionService` 目前**不留任何执行记录**（§2.3 事实 20），而 `SR-2`/`SR-3` 的「以平台侧记录为准」依赖它——不建台账，自审证据只能退回模型自填，等于没改。

**③ 本计划不做什么**（边界，防越界）

1. **不建第二套 Review Runtime、不新增子任务状态**——沿用 `SubTaskStatus` 与既有 REVIEW→REWORK/COMPLETE 链。依据：`doc/HelloAI 项目基线文档.md:373`「现阶段不建立第二套 Review Runtime」红线。
2. **不搬安全审计的领域模型**——六阶段流程、hunting waves、`attack class` 知识库、severity 分级、`scratch→artifacts` 11 步描述符提升均不适用。依据：本项目的判定对象是**单次子任务产出**，不是**整个代码库的攻击面**；`research/` 借鉴判据「只借机制不复制领域内容」。
3. **不让沙箱成为判定者**——沙箱只提供「命令是否执行、退出码、输出」事实，内容达标仍由 reviewer / LLM 判定。依据：`design/adr/ADR-004-sandbox-execution-chain-and-fidelity-gate.md` §4。
4. **不在本批替换缺陷指纹**——`RepeatedFailureGate` 现有三段式判据（评分停滞 + 文本重复 / 自报停滞）已用真机语料校准，替换需独立立项。依据：§8 挂起项。
5. **不在拆解侧降级验收强度**——`RV-1` 命中只**标注/转人工**，不改 `acceptance`、不改 `acceptance_kind`、不自动 `pass=false`。依据：`TD-11`「只标不拒」同款处置（`LOG-20261025-014`）。
6. **不把自审闸门做成第二个 `FinalReportFidelityGate`**——两者判定对象不同（单子任务收尾 vs 终报告），职责边界见 §4 决策 D4。依据：判据「同一事实双写必分叉」。

**④ 诚实边界**

- **`RV-1` 首批只标不拒 ≠ 四处 fail-open 已关闭**：本计划先落地 `Warn` 档（记事件、不改判定），真机语料从 **n=12** 起步（§2.3 事实 20）。**`Warn` 档上线不得宣称「核验契约已强制」**；只有升 `Block` 后该结论才成立。
- **`RV-2` 落 `INCONCLUSIVE` ≠ 人工介入成本已可控**：该态设计为「停 REVIEW 转人工」。上线后**人工待处理会上升**，这是有意取舍（比「空转返工」或「假 pass」更接近真实），但它确实是**新增作业量**。
- **`RV-3` 的 `coverage[]` 依赖模型填 `criterionRef`**：模型不填或填错时，批评器只能判「未覆盖 → `INCONCLUSIVE`」，判不了「其实覆盖了只是没写」。因此该能力的上限是**「漏判可发现」，不是「漏判不发生」**。
- **`SR-1` ~ `SR-4` 落地后「自审真跑过」只在沙箱开启时成立**：`application-quickstart.yml:112` 默认 `enabled=false`，该档位下自审一律走降级（`degraded_no_sandbox`），**不得统计为「已自审」**。
- **`SR-5` 台账只是调用记录，不是执行正确性证明**：它记 `command/exitCode/truncated/digest`，不证明命令本身验的是对的东西。
- **`RV-6` 的误伤率只覆盖有快照的驳回记录**：`V141` 之前的历史驳回（本机 41 条）无快照、返工已覆盖产出，不入样；该指标样本从 0 起步，**不得用首周数字下结论**。
- **`RV-7` 只做 `Warn` 档观测，不等于乱码已被拦截**：检测命中只进 `sub_task_auto_review_verdict_warn`，不改判定；且检的是「可机读的损坏特征」，不含语义层面的错译/乱序。要真正拦住，须在验收标准里加编码断言（本项已改拆解提示词）或升 `BLOCK`（待真实语料证明零误伤）。
- **`RV-1` Block 与 `RV-3` 两个 BLOCK 分支无真机样本 ≠ 未实现**：`reject_with_full_score` / `coverage_absent` / `unconfirmed_silently_dropped` 均由 reviewer 输出形态触发，执行侧（内部/外部 Agent）只能控制交付内容，正常链路无法稳定制造；按单测/IT 收口，计划已标注「不可自然采样」，不主动构造。
- **`G-007` 不因本计划关闭**：本计划只覆盖「reviewer 判定的确定性与可核对性」，`G-007` 的「Rule + Test + LLM 统一决策」还包含 rule 引擎与 test 执行者的统一调度，那层不在本计划。差距表状态按批次完成后回填，**不提前宣称**。

- **落地记录（2026-11-04）**：`FinalReportFenceHook#recordEvidenceObservation` 的 `selfReview` 标签按沙箱开关分流——沙箱开 ⇒ 对账结论（`missing` / `malformed` / `verified` / `mismatch`），沙箱关 ⇒ 常量 `DEGRADED_NO_SANDBOX`（`degraded_no_sandbox`，**不写** verified/mismatch）。两者不混用的理由：`missing` = 「模型该给证据却没给」（自审不合格），`degraded_no_sandbox` = 「平台没给模型一手证据的机会」（环境降级）；同一标签统计会把沙箱关着的自述算进「已自审」。该档位下闸门也不判（`Tier.SKIPPED_NO_SANDBOX`）——没有一手证据可对账，强行判会把「沙箱没开」伪装成「模型自审造假」。payload 另带 `claimedCount / ledgerCount / sandboxEnabled / gateTier / gatePassed`，一条事件读全「跑没跑、判成什么档、拦没拦」。观测面用既有 execution timeline，未新增表。单测：`FinalReportFenceHookTest#sr4_sandboxDisabled_degradesAndNeverClaimsSelfReview`（沙箱关 + 模型自报了「执行过」的证据：事件必发、`selfReview` 恰为 `degraded_no_sandbox` 且显式断言**不在** `verified/mismatch/malformed` 内、`gateTier=SKIPPED_NO_SANDBOX`、降级档不重跑 `callCount==2`）。

- **降级**：沙箱未启用 ⇒ 事件 `self_review=degraded_no_sandbox`；自审结论仍可提交，但 reviewer 侧显式看到「无一手证据」，按既有从严规则处理。
- **观测**：自审证据写 execution timeline payload（既有观测面），暂不新增表；跨轮查询需求出现后再考虑落 JSONB。
- **验收**：① 单测：`enabled=false` 时事件必发；② 该档位下统计口径**不计入「已自审」**（有断言）。

### SR-5 沙箱调用台账

> **状态**：已完成（真机验收通过 2026-11-04）｜ **剩余动作**：—

- **落地记录（2026-11-04）**：`SandboxCallLedger`（`agent/runtime/sandbox`，进程级 ring buffer：每子任务 50 条 / 最多 512 子任务 LRU）+ `ExecuteResponse#digest()`（派生方法，零调用点改动）+ `OpenSandboxExecutionService#recordCall`（台账 + `sandbox_command_executed` 事件，经 `agent.port.TaskTimelinePort` 写入避免反向依赖；入口守卫不登记，超时/异常照常入账）。单测 `SandboxCallLedgerTest` 6 例、`OpenSandboxExecutionServiceTest` 新增 4 例（含 `digest` 与 `"abc"` 已知值对账）。 **真机验收（2026-11-04）**：`sandbox_command_executed` 回读到 6 条（第一轮 3 个子任务各 2 条）；**已知限制**：事件 `task_id` 为空，任务级时间线需按 `sub_task_id` join，跨层补 taskId 留待后续。

- **动因**：`OpenSandboxExecutionService.execute` 现只有 `log.info/debug`，**没有任何可回读记录**（§2.3 事实 23）。`SR-2`「以平台侧记录为准」没有它就不成立，只能退回解析模型自填 —— 即本计划要消灭的「自述」。
- **形态**：`ExecuteResponse` 增 `digest`（输出 sha256）；执行后按 `subTaskId` 记一条 timeline 事件（`command` 前 200 字符 + `exitCode` + `truncated` + `digest`），并提供按 `subTaskId` 读取近 N 条的查询面。
- **`digest` 的落法（评审补充）**：`ExecuteResponse` 是 **3 字段 record**（`output/exitCode/truncated`，`ExecuteResponse.java:14`），全库 `new ExecuteResponse(` **22 处**（主代码 7 + 测试 15）⇒ 作为 record 分量会改爆所有调用点。改为**派生实例方法** `digest()`（对 `output` 算 sha256）或保留 3 参紧凑构造，一处实现、零调用点改动。
- **`digest` 的语义边界**：它算的是**可能已截断**的 `output`（100KB 上限 + `truncated=true`），因此只能证明「台账条目与模型自填指向同一份输出」，**不是**完整输出的完整性证明；台账条目必须同时记 `truncated`，否则截断场景下会给出过强结论。
- **不做的**：不落独立表（先用 timeline，避免为一次性需求建表）；不存完整输出（只存 digest + 前缀，正文仍在 `ExecuteResponse`）。
- **验收**：① 单测：台账条目字段齐全、`digest` 与输出一致；② IT：一次沙箱调用后可从 timeline 回读到该条；③ 超时(124)/SDK 异常(-1) 同样入账。

## 4. 关键设计决策

| # | 决策 | 取舍与理由 |
|---|---|---|
| D1 | `RV-1` **分级处置**（`Block` 只留逻辑矛盾项，其余 `Warn`），而非一次全 `Block` | 真机 `review_record` 仅 12 条（§2.3 事实 20），其中 `Warn` 四项**零命中**。零命中在 n=12 上证明不了「不会误伤」，只能证明「没观察到」。全 `Block` 上线会把「模型漏写 analysis」变成「全量转人工」。故先 `Warn` 埋点，n≥50 再议。对齐 `TD-11`「只标不拒」先例。 |
| D2 | `RV-3` 覆盖判据用 **`criterionRef` 子串归属**，不用「条数相等」 | 实测 `acceptance` 半角 `;` **0 命中**、全角 `；` 9 条、圈号仅 5 条，且存在条目内嵌套 `；`（§2.3 事实 21）。按「分号拆分」实现必然过拆或全拆成 1 条 ⇒ `条数相等` 判据几乎必然失败 ⇒ 全量 `INCONCLUSIVE`。子串归属对分隔符风格不敏感，且与 `missingEvidence.acceptanceRef` 复用同一匹配器。 |
| D3 | `SR-5` 台账**前置**于 `SR-2`/`SR-3` | 平台无执行记录（§2.3 事实 23），「以平台侧记录为准」缺少事实源。不建台账则自审证据只能读模型自填，等于没改。 |
| D4 | `SR-3` 与 `FinalReportFidelityGate` **判不同对象、只共享结构** | 两者都问「证据是否存在」，但一个判单子任务收尾轮、一个判终报告脚本。若合成一个闸门，则「子任务证据」与「终报告证据」双写一算，必分叉（判据 4）。 |
| D5 | 三态新增 `INCONCLUSIVE` 而**不**复用 `REJECTED` | 「证据不足」与「质量不达标」的处置相反：前者该转人工（不该返工），后者该返工。混装会让返工预算被空转消耗（与 `TD-11`/`TD-12` 同源病根）。 |
| D6 | 沙箱只提供事实，**不做判定** | `exitCode=0` 不等于内容达标（脚本可能只验证了无关的事）。判定权留在 reviewer / LLM，与 ADR-004 §4 一致。 |
| D7 | 缺陷指纹替换**挂起** | `RepeatedFailureGate` 已用真机语料校准（真停滞相似度 0.18~0.25，故加评分停滞第二条件）。替换需对照实验，不与本计划混批。 |

## 6. 风险与边界

| 风险 | 缓解 |
|---|---|
| 收尾轮放开工具 ⇒ 成本上升 / 滥用 | 仅一个工具 + 基线差值上限 `N=3` + 既有超时/输出截断；配置可关；总调用数上限 `2 × (1 + K)` 入单测 |
| `RV-2` 后人工待处理上升 | 预期内取舍（§0④）；`INCONCLUSIVE` 不计入驳回率/返工预算，避免二次污染；看板单列该态计数 |
| `INCONCLUSIVE` 污染既有统计 | `ReviewRecordMapper` 三处 SQL 同批改分母（§2.1 事实 12），单测断言 |
| `coverage` 依赖模型填 `criterionRef` | 填错只会「多判 INCONCLUSIVE」，不会误放行；批评器不做内容判断 |
| 三态影响前端 | 按 `result` 枚举渲染；未知值降级为「其他」；`INCONCLUSIVE` 独立配色 |
| 自审重跑放大 LLM 轮数 | `K=1` 默认；事件记重跑次数与原因；乘数关系写进配置注释 |
| 判定快照存储增长 | 只存附件版本 ID + 输出摘要（长度 + sha256），不存全文 |
| `SR-` 与 `S-` 前缀视觉混淆 | 文档一律写全 `SR-`；出现实际歧义改 `SF-x` 并同批修正引用 |

## 7. 验证方案

1. **单测**：`ReviewVerdictValidator`（表驱动 ≥20 例：四象限 + 假子串 + 宽松解析 + 空 `analysis`）；`ReviewCoverageParser`（圈号拆分、条目内嵌套 `；` 不误拆）；`SelfReviewGate`（三档判定）；`SelfReviewEvidenceParser`（非法形态不抛）；`ReviewRecordMapper` 分母排除断言；**`createReview` 入口白名单拒绝 `INCONCLUSIVE`**；**覆盖批评器对 `ASSUMPTION` 不误判**；**收尾轮 `N=3` 计数装饰器（第 4 次被拒）**。
2. **IT**（`*IT` 增量三类）：① 三态路由（`INCONCLUSIVE` 停 REVIEW、`rework_count` 不变）；② 自审轮可调沙箱 + `N=3` 基线差值生效 + 失败重跑恰好一次；③ 沙箱关闭 ⇒ `degraded_no_sandbox` 事件。
3. **真机**：一条脚本类子任务（要求 `exitCode=0` 证据）+ 一条文档类子任务（走覆盖比对）+ 一轮 `RV-1` `Warn` 埋点观察（确认判定结果零变更）。
4. **门禁**：`bash scripts/ci/ci-gate.sh` 全绿；新增事件码须过 `scripts/shell/verify-event-key-parity.sh`；本文已纳入 `scripts/shell/verify-plan-status.sh` 白名单。
5. **`RV-6`**：`REJECTED→APPROVED` 记误伤且 direction 正确；`REJECTED` 无快照不入样；`INCONCLUSIVE` 原判不入样；驳回优先入样且批量上限生效（单测 + IT）。
6. **`RV-7`**：`ReviewEncodingDetectorTest` 8 例（三类信号 + 正常中文/正常西文反证 + detail 截断）；`ReviewExecutionEngineTest` 断言乱码只产 `WARN` 且 `enforced=false`、开关独立可回滚；**真机已通过**（夹具 `2118312647812317186`：时间线命中 `output_encoding_corrupted`、判定仍 `APPROVED/4`；外部 Agent 中文交付零误报；拆解 4/4 草案自动补编码断言）。
7. **不可自然采样分支（2026-11-05 标注）**：`reject_with_full_score`（RV-1 Block）、`coverage_absent` / `unconfirmed_silently_dropped`（RV-3）均由 reviewer 输出形态触发，执行侧（内部/外部 Agent）无法控制；以 `ReviewVerdictValidatorTest` / `ReviewCoverageCriticTest` + 引擎接线单测覆盖。真机仅等待自然出现样本并由 `sub_task_auto_review_verdict_warn` 回填，**不主动构造**。
