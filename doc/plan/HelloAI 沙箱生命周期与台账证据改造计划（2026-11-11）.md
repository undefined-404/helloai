## 0. 定位与边界（★先读）

### ① 问题来源

- **S-7 沙箱每轮销毁**：`LocalExecutionCommandConsumer` 在 turn 结束 `release(subTaskId)`（[LocalExecutionCommandConsumer.java:156-171](file:///E:/yhzx/1027/helloai/helloai-core/src/main/java/com/helloai/core/agent/mqconsumer/LocalExecutionCommandConsumer.java#L156)）。真机第 5 轮开工时 `/workspace` 为空（16:00:43 `ls` 只有 `.`/`..`），模型每轮重建上游文档、重复探索；5 轮共 72 条沙箱命令（70 条不同），`ls -la /workspace`、`cat verify_out.txt`、重写 `verify.py` 均出现重复。
- **S-3/S-4 证据对账脆弱**：模型自报 `EVIDENCE` 用「`cat > v7.py <<'PYEOF' ... python3 v7.py`」这类省略式命令，与台账「真实命令前 200 字符」做前缀匹配必然失败（[SelfReviewEvidenceVerifier.java:111-132](file:///E:/yhzx/1027/helloai/helloai-core/src/main/java/com/helloai/core/agent/runtime/loop/impl/SelfReviewEvidenceVerifier.java#L111)）；台账每子任务只保留 50 条（[SandboxCallLedger.java:36](file:///E:/yhzx/1027/helloai/helloai-core/src/main/java/com/helloai/core/agent/runtime/sandbox/SandboxCallLedger.java#L36)），而本轮 72 条，早轮证据被淘汰。真机 `self_review_evidence_checked` 的 `ledgerCount` 从 15:59 起恒为 50，mismatch 全部指向省略式命令。
- **外部对照结论**：三个参考项目**没有一个**在 turn 边界销毁工作区——DSH 的 cwd 就是项目目录、持久 shell 跨 turn 存活；OpenSandbox 官方用法是 `taskId → sandboxId`、按 ID 重连、不要每轮 destroy；octop 的工作区按 Agent 持久、`close` 与 `destroy` 分离。详见 §9。

### ② 本计划做什么

1. **沙箱寿命改为任务级、终态销毁**（`SL-1` + `SL-2`）：槽键从 `(subTaskId, spec)` 改为 `(taskId, spec)`；删除 turn 结束释放；任务 `DONE` / `CANCELLED`（含级联删除）时经事件在事务提交后释放该任务全部沙箱。会话内技能执行（非子任务 ID）继续走原 `scope:{id}` 语义。
2. **工作区语义与回读修正**（`SL-3`）：任务根 `/workspace` 作为共享工作区（首期不做子任务子目录）；`readWorkspaceFile` 改为取「最近修改」的 `.md`；Prompt / 工具说明同步。
3. **证据改为台账条目引用**（`SL-4` + `SL-5`）：台账条目加平台生成 `callId` 并随执行结果返回；围栏 `EVIDENCE` 从「自报命令 + 摘要」改为 `{"kind":"sandbox_exec","callId":"c17"}`；新增 `internal_list_sandbox_calls`；旧格式保留一版兼容。
4. **验证与灰度收口**（`SL-6`）：单测 / 集成 / 真机（返工续作、跨子任务可见、终态销毁、证据引用）与 `scope=task|subtask` 回滚开关。

### ③ 本计划不做什么

1. **不把任务级沙箱当成「子任务隔离」**：同一 Task 的子任务共享 `/workspace`，这是**有意放宽**（上游产物天然可见、返工可续作），安全边界从「子任务」上移到「Task」。子任务子目录隔离列入 §8 挂起项，不在本批。**依据**：用户 2026-11-11 口径「task 级沙箱」；ADR-005 既有「同子任务复用」语义上移一层。
2. **不把对象存储附件水合进沙箱**：上游已物化附件仍在对象存储，本批只解决「沙箱内产生的文件跨轮/跨子任务可见」；`storageUrl` 可满足性问题另批处理。**依据**：差距表 `G-029` 已登记「上游附件 storageUrl 不可达」，其修复面大于沙箱生命周期。
3. **不做 G-030 自审 fail-close**：本批先把「证据是否可信」修好（`SL-4`/`SL-5`），`self_review_failed → 不提交` 的出口收口必须在证据链可靠后再上，否则误判会把正常任务全拦。**依据**：差距表 `G-030`；用户 2026-11-11 要求本批只做沙箱与证据引用。
4. **不做跨进程重启的沙箱重连**：槽池仍是进程内内存；重启后工作区丢失、旧容器由绝对 TTL 回收。持久化映射列入 §8。**依据**：ADR-005 将沙箱定义为进程级资源，本批不改变该边界。
5. **不改外部 Agent 的沙箱**：外部 CLI Agent（trae / qoder）自带工作区，不在本链。**依据**：外部执行者职责手册（`doc/manual/executor-duty/`）与 `G-014` 外部通道口径。
6. **不改 Action/状态机语义**：`DEAD_LETTER`、`RESTRUCTURING`、任务重派/重构仍按既有状态机流转。**依据**：ADR-008 与「状态迁移唯一入口」约束（`SubTaskStateMachineServiceImpl`）。

### ④ 诚实边界

- **任务级共享 ≠ 数据隔离**：同任务的不同执行者可以读/改彼此的文件；首期用「同槽命令串行」防止并发写坏，但语义上不隔离。若需要强隔离，走 §8 的子目录方案。落地后**不得在差距表把 `G-032` 标为「已完成」直到真机验证通过**。
- **同任务多规格 = 多个沙箱**：python 与 node 规格键不同，文件不互相可见；跨规格共享必须走对象存储导出，不在本批。
- **销毁是「尽力而为」**：任务终态事件丢失、进程崩溃、SDK 不可达时，由空闲 TTL 与沙箱绝对 TTL 兜底回收；不承诺即时。
- **`callId` 只证明「这条命令确实执行过且输出摘要一致」**，不证明命令验的是对的东西；内容正确性仍归 reviewer。
- **旧证据格式保留兼容**：`command + exitCode + truncated + digest` 仍可解析、仍走旧匹配，但只做一版过渡，后续可删。
- **本计划完成不关闭 `G-029` / `G-030`**：`G-029` 的附件水合与 `G-030` 的出口 fail-close 仍是独立差距；`G-032` 只覆盖沙箱生命周期与证据引用本身。

## 3. 任务表（`SL-1` ~ `SL-6`）

### SL-1 任务级作用域 + `releaseByTask`

> **状态**：待开始 ｜ **剩余动作**：实现 scope 解析 / `releaseByTask` / 开关，并补 `OpenSandboxExecutionServiceTest`（§7）

- **落点**：`OpenSandboxExecutionService`、`SandboxExecutionService`、`SandboxSlotPool`（键语义不变）。
- **做法**：
  1. `SlotKey` 改为 `(Long scopeId, String specFingerprint)`，语义由调用方决定；新增 `SandboxScopes` 解析：
     - `subTaskId` 能经 `SubTaskQueryPort.findById` 命中 ⇒ `task:{taskId}`；
     - 未命中（如会话技能 `scopeId`）⇒ `scope:{id}`，保持现状；
     - 解析结果做小容量 LRU（如 1024）缓存，任务终态时失效。
  2. `SandboxExecutionService` 新增 `releaseByTask(Long taskId)`（默认空实现）；实现按 `task:{taskId}` 匹配删除全部规格槽。
  3. 新增开关 `helloai.sandbox.opensandbox.scope = task|subtask`（默认 `task`，`subtask` 仅用于回滚/排障）。
- **验收**：同一任务下两个子任务命中同一个默认规格沙箱；不同任务互不复用；会话技能 `scopeId` 行为不变；`releaseByTask` 只清目标任务。
- **测试**：`OpenSandboxExecutionServiceTest` 扩展（scope 解析、缓存失效、releaseByTask）；`SandboxSlotPoolTest` 按谓词删除多槽。

### SL-2 终态销毁接线

> **状态**：待开始 ｜ **剩余动作**：新增 `TaskTerminalStateEvent` + 监听器，改三个终态入口并删除 turn 末释放，补事件/并发单测（§7）

- **落点**：`com.helloai.core.shared.event.TaskTerminalStateEvent`（新增）、`TaskLifecycleServiceImpl`、`TaskServiceImpl`、agent 域新增 `SandboxTaskTerminalListener`、`LocalExecutionCommandConsumer`。
- **做法**：
  1. 任务域在以下位置发布事件：`tryCloseTask` CAS 成功后（`DONE`）、`updateStatus(DONE/CANCELLED)`、`deleteTaskCascade`（`trigger=deleted`）。
  2. 监听器 `@TransactionalEventListener(phase = AFTER_COMMIT, fallbackExecution = true)` → `releaseByTask`，失败只 warn（幂等，重复事件无副作用）。
  3. 删除 `LocalExecutionCommandConsumer` 的 turn 末 `release(subTaskId)`。
  4. `releaseByTask` 对每个匹配槽 `tryLock(5s)` 后再销毁；拿不到锁说明有在跑命令，跳过并交给 TTL。
- **验收**：任务 `DONE` / `CANCELLED` / 删除后 `activeSandboxes()` 归零（目标任内）；子任务 `DEAD_LETTER`/`BLOCKED` 且任务 `IN_PROGRESS` 时沙箱保留；rework 开工能看到上一轮文件。
- **测试**：单测事件发布点（三个入口各一）；监听器幂等/异常吞掉；releaseByTask 与并发执行的互斥。

### SL-5 证据引用化 + 查询工具

> **状态**：待开始 ｜ **剩余动作**：解析/对账/闸门改造 + 新增 `internal_list_sandbox_calls` + 旧格式兼容，补证据链单测（§7）

- **落点**：`SelfReviewEvidenceParser`、`SelfReviewEvidenceVerifier`、`SelfReviewGate`、`FinalReportFenceHook` 围栏模板、`InternalLlmExecutorTools` 新增 `internal_list_sandbox_calls`。
- **做法**：
  1. 新格式：`EVIDENCE: [{"kind":"sandbox_exec","callId":"c17"}]`；`callId` 必填，旧字段可选（兼容）。
  2. 解析：`callId` 优先；缺失时按旧四字段解析（旧格式保留一版，日志标 `evidence_schema=legacy`）。
  3. 对账：`callId` 在台账中存在 ⇒ 已验证；不存在 ⇒ `MISMATCH`。自报 `exitCode/command` 若同时提供且与台账矛盾，记 mismatch（防伪造）。
  4. 闸门：`SANDBOX_REQUIRED` 档要求「引用的条目全部存在，且至少一条 `exitCode=0 && !truncated`」；未引用任何条目仍判失败。
  5. 新工具 `internal_list_sandbox_calls(limit=20)`：返回最近调用 `callId + commandPreview + exitCode + truncated + digest + at`，让模型引用而不是手抄。
  6. 收尾指令模板：`EVIDENCE` 行改为引用 `callId`；提示可直接使用工具返回的 `callId`。
- **验收**：模型自报省略式命令不再产生 mismatch；真机 `self_review_evidence_checked` 为 `verified`；引用不存在 `callId` 能被拦；旧格式仍可跑。
- **测试**：Parser（新旧两版、混合、非法）；Verifier（命中/未命中/矛盾/去重）；Gate（引用成功/引用失败/无引用）；工具契约（返回字段、limit 上限）。

## 4. 关键设计决策

| 决策 | 选择 | 理由 / 备选 |
| --- | --- | --- |
| `D1` 作用域 | **Task 级**（`task:{taskId}`），会话技能保留 `scope:{id}` | 用户口径；OpenSandbox 官方 `taskId→sandboxId`；比子任务级更能解决上游可见与返工续作。备选：子任务级（不改上游可见性） |
| `D2` 工作区布局 | **首期共享 `/workspace`**，不做子任务子目录 | 改动最小、与现有 Prompt 路径兼容；代价是跨子任务可见（有意为之）。子目录 + cwd 注入列入 §8 |
| `D3` 销毁时点 | 任务 `DONE/CANCELLED`（含删除），事件 AFTER_COMMIT | `DEAD_LETTER` 子任务仍可能重派；turn 结束不销毁。备选：显式管理端点（增加运维负担） |
| `D4` 证据标识 | 平台生成 `callId`，模型只引用 | 消灭「手抄命令」这一脆弱环节；比 digest 自算可靠；`digest` 仍保留用于防伪 |
| `D5` 台账容量 | 200 条/子任务，查询工具只列 50 | 覆盖单次长执行；内存可控（512 子任务 × 200） |
| `D6` 兼容 | 旧 `EVIDENCE` 四字段保留一版 | 避免存量任务与旧模型立即失效；日志标记 legacy，下一版删 |
| `D7` 并发 | 同槽命令串行（既有 `Slot.lock`） | 跨子任务共享时至少不并发写；语义隔离不做 |
| `D8` 空闲 TTL | 默认 900 → **7200**（2h），每次命令 `renew` | 人工审查/长任务间隔可能超过 15min；配合沙箱绝对 TTL 由 renew 延长 |
| `D9` 灰度 | `sandbox.opensandbox.scope=task|subtask` | 出问题可一键回退到旧语义；回滚不迁移数据（内存态） |

## 6. 风险与边界

1. **跨子任务文件污染**：任务级共享后，B 可能误读/覆盖 A 的文件；靠命令串行与 Prompt 约束，不做强制隔离（§8 子目录方案）。
2. **多规格不共享**：同一任务 python/node 两个沙箱，文件不互通；跨规格交付应走 `internal_export_artifact`。
3. **重启丢工作区**：进程重启后槽池清空，旧容器靠 TTL 回收；任务若需继续，会新建沙箱、旧文件丢失（已有行为，不恶化）。
4. **终态释放与在跑命令竞争**：`releaseByTask` 用 `tryLock`；拿不到锁的槽交给 TTL，避免杀正在执行的命令。
5. **对话作用域误判**：`SubTaskQueryPort.findById(scopeId)` 未命中即按 `scope:{id}`；需加单测防「conversationId 恰好等于某个 subtaskId」的极端碰撞（雪花 ID 概率可忽略，但保留判据）。
6. **台账内存增长**：200×512 上限；任务终态可主动清理该任务下子任务的台账（`SL-2` 顺带），避免长期驻留。
7. **证据引用不校验内容**：`callId` 只证明执行事实；报告内容仍需 reviewer。
