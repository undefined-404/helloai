> 目标：提供"用户输入任务 → 跳过 planner → 直派 1~N 个 EXECUTOR"的可视化入口，作为 M5 联调的派单工具。

> 纪律：遵循 `doc/HelloAI_CODE_STYLE.md`；Controller 返回 DTO 不返回 Entity；前端 Long ID 一律 string（后端已全局序列化）。

## 1. 后端改动（helloai-api）

### 1.1 【新建】`dto/subtask/TaskTimelineItem.java`

```java
package com.helloai.api.dto.subtask;

import lombok.Data;
import java.time.OffsetDateTime;
import java.util.Map;

@Data
public class TaskTimelineItem {
    private Long id;
    private String eventType;
    private String role;
    private Long agentId;
    private Map<String, Object> payload;
    private OffsetDateTime createTime;
}
```

### 1.2 【改】`controller/SubTaskController.java` 追加两个端点

在类中注入 `TaskTimelineService`（构造器注入，与现有一致），追加：

```java
private final TaskTimelineService taskTimelineService;

/** M4.5：批量派发——同一任务内容派给多个 EXECUTOR（fan-out 语义 A：一 Agent 一子任务）。
 *  逐项独立创建（各项自身事务），中途失败不回头：返回成功/失败明细，便于派发工具定位。 */
@PostMapping("/batch")
public R<List<SubTaskResponse>> createBatch(@Valid @RequestBody List<CreateSubTaskRequest> reqs) {
    List<SubTaskResponse> created = new ArrayList<>();
    for (CreateSubTaskRequest req : reqs) {
        created.add(create(req).getData());   // 复用现有单建逻辑，不复制装配代码
    }
    log.info("子任务批量派发: total={}, success={}", reqs.size(), created.size());
    return R.ok(created);
}

/** M4.5：子任务执行时间线（联调可视化）。 */
@GetMapping("/{id}/timeline")
public R<List<TaskTimelineItem>> timeline(@PathVariable("id") Long id) {
    List<TaskTimelineItem> items = taskTimelineService.lambdaQuery()
            .eq(TaskTimeline::getSubTaskId, id)
            .orderByAsc(TaskTimeline::getId)
            .list()
            .stream().map(e -> {
                TaskTimelineItem it = new TaskTimelineItem();
                it.setId(e.getId());
                it.setEventType(e.getEventType());
                it.setRole(e.getRole() != null ? e.getRole().name() : null);
                it.setAgentId(e.getAgentId());
                it.setPayload(e.getPayload());
                it.setCreateTime(e.getCreateTime());
                return it;
            }).toList();
    return R.ok(items);
}
```

注意点：
- `import` 补齐：`java.util.ArrayList/List`、`com.helloai.core.task.service.TaskTimelineService`、`com.helloai.core.task.entity.TaskTimeline`、`com.helloai.api.dto.subtask.TaskTimelineItem`；
- `createBatch` 直接调用本类 `create(req)` 复用装配与 autoAssign 逻辑，**禁止复制粘贴 create 的方法体**；
- `create(req).getData()` 取 `R<SubTaskResponse>` 载荷；若某项 create 抛 BizException，允许整体 500——由前端循环兜底报告明细（见 2.3，前端默认逐项调用，batch 端点作为可选加速路径）。

## 2. 前端改动（helloai-ui）

### 2.1 【新建】`src/api/module.ts`

```ts
import request from './request'

export interface ModuleItem { id: string; taskId: string; name: string; description?: string; sortOrder?: number }

export const moduleApi = {
  list(taskId: string) {
    return request.get<any, ModuleItem[]>(`/tasks/${taskId}/modules`)
```

### 2.4 【新建】`src/components/QuickDispatchDialog.vue`（核心组件）

职责：一个对话框完成"选任务 → 选模块 → 填内容 → 勾选 1~N 个 EXECUTOR → 派发"。

- 表单字段：任务（el-select，`taskApi.list()`）、模块（el-select，随任务联动 `moduleApi.list(taskId)`，含"+ 新建模块"行内输入调 `moduleApi.create`）、标题、任务内容 description（textarea）、验收标准 acceptance（textarea）、优先级（el-select HIGH/MEDIUM/LOW，默认 MEDIUM）、执行 Agent（el-select **multiple**，数据源 `agentApi` 的 EXECUTOR 列表，复用现有 AgentSelect 的数据加载方式）；
- 提交逻辑：**逐项循环** `subTaskApi.create({...form, assignedAgent: agentId })`（Promise.allSettled），不使用 batch 端点——保证单个失败不影响其余，且能逐 Agent 报告结果；
- 结果反馈：el-message 汇总"成功 N / 失败 M"，失败项列出 Agent 名与错误信息；全部成功后 emit('done') 由父页面刷新列表；
- 校验：标题/内容必填，至少选 1 个 Agent；
- Agent 下拉只列 `role=EXECUTOR` 且 `accessType=CLI_CLIENT` 的项，值班中的名前标注"（值班中）"（数据来自 duty 接口，可选增强，标 TODO 即可）。

### 2.6 【改】`views/subtask/SubTaskDetail.vue`（执行时间线可视化）

- 新增"执行时间线"卡片（el-card + el-timeline），数据源 `subTaskApi.timeline(id)`；
- 每条节点显示：`eventType` + `role/agentId` + `fmtTime(createTime)`，payload 用 `<el-collapse>` 折叠展示 JSON；
- **轮询**：详情页打开期间每 5s 刷新一次时间线与子任务状态；子任务进入终态（COMPLETED/CANCELLED）后停止；组件卸载 `clearInterval`；
- 风格与现有页面保持一致（参考 DutyLeaseList 的卡片样式）。

## 3. 验收用例（AC）

| # | 用例 | 操作 | 预期 |
|---|---|---|---|
| AC1 | 新建任务 | 任务管理 → 新建任务（对话框或 API） | 列表出现新任务，状态初始正确 |
| AC2 | 单 Agent 派发 | 快速派发选 qoder 一个 Agent | 生成 1 个子任务，`assigned_agent_id`=qoder；qoder 门铃秒级响；`agent_inbox` 一行 |
| AC3 | 多 Agent fan-out | 同一内容勾选 qoder + trae | 生成 2 个**独立**子任务，各自指派、各自响铃、互不影响 |
| AC4 | 失败容错 | 派发时使其中一项失败（如停掉一个 Agent 后仍勾选，或构造非法数据） | 成功项照常创建，对话框明确报告失败项与原因，不整单回滚 |
| AC5 | 时间线实时性 | 派单后打开子任务详情 | 5s 内看到 `sub_task.assigned`；AI claim 后看到 `IN_PROGRESS` 流转，无需手动刷新 |
| AC6 | 回归 | 跑 `scripts/powershell/verify-onboarding-pull.ps1` | 全绿（确认新端点不影响既有链路） |
| AC7 | 规范 | CODE_STYLE 检查 | Controller 返回 DTO；无 Mapper 注入；新 API 路径符合 6.4/6.5 规范 |
