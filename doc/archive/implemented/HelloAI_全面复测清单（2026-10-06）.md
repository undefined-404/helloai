## 5. ★新增专项：无候选兜底 + 倒计时（时钟 C）

> **本轮最高优先级**——从未真机跑过。**建议用「确定性构造」而非「抢占用」**：把 `agent_policy.executorAgentIds` 钉到一个**离线/不存在**的 agent ⇒ 永远无候选，可稳定复现。

### 5.1 加速配置（仅测试期临时调小，验完改回）

```yaml
helloai:
  dispatch:
    no-candidate-max-rounds: 2                    # 默认 10，测试期调到 2 加速
    no-candidate-retry-interval-seconds: 10       # 默认 120，测试期调到 10
    no-candidate-retry-jitter-seconds: 0          # 默认 15，测试期关抖动便于断言
```

### 5.2 步骤与判据

| 步 | 操作 | 判据 | 结果 |
|---|---|---|---|
| N-1 | 建任务，`agentPolicy.executorAgentIds=[<离线agent>]`；确认草案 → 触发自动分发 | 子任务停在 `PENDING`，timeline 落 `sub_task_no_candidate` | ☐ |
| N-2 | 查 DB：`select context->'noCandidate' from sub_task where id=<sid>` | 出现 `rounds=1`、`nextDispatchAt ≈ now+interval`、`reason`、`firstSeenAt` | ☐ |
| N-3 | 前端子任务详情 | 显示「等待执行者 · 约 N 秒后重试」，**逐秒递减** | ☐ |
| N-4 | 等一个扫描 tick（60s）、`nextDispatchAt` 未到 | **本轮跳过**（日志 `skipWaiting`），不重试、不改 rounds | ☐ |
| N-5 | 等 `nextDispatchAt` 到 → 再选人 → 仍无候选 | `rounds=2`、`nextDispatchAt` 再 +interval | ☐ |
| N-6 | 连续到 `rounds = max` | 写 `manualIntervention.reason=no_candidate_long_wait`（事件 `sub_task_manual_intervention_required`）**且 `noCandidate` 键被清除** | ☐ |
| N-7 | 达阈值后再等一个 tick | 被 `isManualInterventionMarked` **跳过**、不再空转、不再累加 | ☐ |
| N-8 | 前端（达阈值后） | 显示「等待人工介入」（隐藏倒计时） | ☐ |
| N-9 | **恢复路径**：人工改派 / 清标记后重开 | 计数归零、恢复自动派发；`waitedMs` 为新窗口（不偏大） | ☐ |

### 5.3 观测 SQL（本地 docker PG）

```sql
-- 无候选状态
select id, status, attempt_total, last_attempt_time,
       context->'noCandidate'  as no_candidate,
       context->'manualIntervention' as manual
from sub_task where id = <sid>;

-- 相关 timeline 事件
select event_type, create_time
from sub_task_event where sub_task_id = <sid>
order by create_time desc limit 20;
```

### 5.4 边界反证（顺手测，成本低）

- `context` 中已有其它键时，写 `noCandidate` **不得丢**其它键（尤其已存在的 `manualIntervention`）。
- `nextDispatchAt` 写成**非法时间串** ⇒ 应降级为「立即尝试」，**不抛异常、不中断整轮扫描**。
- 选中人成功后 `noCandidate` **必须被清除**（否则下一轮误判）。
