## 一、目标格式规范（执行后体例）

### 1.1「处置」列以九态词开头（`协作规约 §6.3`）

`TODO / DESIGNING / IMPLEMENTING / VERIFYING / DONE / PARTIAL / BLOCKED / DEFERRED / WONTFIX`

四条配套取舍：
- **A**：「当前状态」列**禁用**状态词，改用事实语——两列都表状态是新漂移源。
- **B**：一行一个状态词；子项状态不同取**最需关注态**，偏序 `BLOCKED > DEFERRED > PARTIAL > TODO > DESIGNING > IMPLEMENTING > VERIFYING > DONE`，明细写在状态词之后。
- **C**：`WONTFIX` 只用于整行都不做；单子项不做写 `DONE · 附：X 子项 WONTFIX`。
- **D**：不加进度百分比列；量化用子项计数（`未达成 3 项`）。

### 1.2 两列写法

```
当前状态：<事实断言 1>；<事实断言 2>；……   槽位按「契约 → 存储 → 传递」排序
处置：     <九态词> · <未达成项 / 阻断 / 观察点>；<durable 锚点指针>
禁止（两列同）：日期、PASS/全绿/0 失败、用例数、commit hash、`Foo.java:行号`、
                批次/分期标签（批次一~四 / S1~S7 / P1-3 / T01~T08 / 增量 A-D）、
                施工动词（已落地 / 已修复 / 新增 N）、脚本名清单
```

> 注：**「已删除」不属禁止项**——「X 已删除」是状态断言（描述现在不存在），与「删除 X（日期）」的过程叙述不同。守卫脚本据此划定禁止集。

### 1.3 详述小节判据树（**段落级**判定）

每个自然段独立过四问，取**第一个命中**者：

| 问 | 命中 ⇒ 归属 | 判据 |
|---|---|---|
| Q1 是否陈述「当前 ↔ 目标的差」（缺什么 / 未达成 / 触发条件 / 阻断）？ | **留表** | 出现「未达成/尚缺/未做/待/触发条件/阻断」且有明确对象 |
| Q2 是否陈述**对未来实现有约束力的规则/决策/边界**（代码不自明）？ | **迁 `design/`** | 句形「取 X 不取 Y」「A 必须经 B」「粒度 = C」 |
| Q3 是否陈述「做过什么 / 验过什么」（日期/批次/用例数/提交号/行号/DB 计数/脚本）？ | **迁 `log/`**（或确认已有归属） | 命中 §1.2 机械信号 |
| Q4 同一事实是否已在活文档别处逐字存在？ | **删，留锚点** | `grep -F` 在 design/plan/log/manual 命中 ≥1 |

**两条硬约束**：① **先 Q2 后 Q3**（先抽走设计再送过程，否则设计价值被一并冲进 Log，即「整段删会连带丢事实」的成因）；② **Q2 迁移前必须 `grep` 去重**（否则制造第二份副本，未来必然漂移）。
