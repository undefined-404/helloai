## 0. 定位与边界（★先读）

### ① 问题来源

- **A-1（操作级缺口）**：对外执行通道 13 工具无 cancel——executor 认领后卡死/放弃时，平台侧只能改库或等租约过期；子任务状态机本就有 →CANCELLED 出边（10 个非终态全在，`[实测]` SubTaskStateMachine.java:15-43），缺的只是 MCP 工具面入口。ADR 定性：**与 A2A 无关的独立缺陷，收益先到**。
- **A-4（命名解耦）**：13 个 SSE 工具的 `sessionId`/`_sessionId` 参数名与 MCP 传输层会话概念混淆——该 ID 实为 **Redis 鉴权上下文的键**（`helloai:mcp:session-auth:{id}`，McpAuthContext.java:69），即「鉴权会话」，与 spring-ai 传输 sessionId 是两回事（传输层 1.1.x 根本不自动透传，客户端须显式带参）。A2A 入站（C 档）若复用同名参数会语义撞车，先解耦。

### ② 本计划做什么

1. **A-1**：新增 `cancelSubTask` MCP 工具，三通道（SSE / REST 直通 / JSON-RPC）+ 授权/注入清单 + 显示名 + 守卫脚本 + 契约测试 + onboarding 文档。
2. **A-4**：SSE 通道 14 个工具（含新 cancelSubTask）加新推荐参数名 **`authSessionId`**，优先级 `authSessionId > sessionId > _sessionId`，旧两名保留一个周期（ADR「加新名 + 旧名保留一个周期」口径）。

### ③ 本计划明确不做

- **A-2（submitResult.parts）/ A-3（contextId 预留）**：需先拍板 AQ-7 / AQ-4，用户未裁定，本批不动。
- **B/C 档**（出站 client / 入站 server）：ADR 排期在主线闭环后 / G-033 有解后。
- **状态机改动**：零。cancel 复用既有 `SubTaskStateMachineServiceImpl.cancel`（:319，存在性 + DONE/CANCELLED 守卫）→ `changeStatus`（attempt 收口 / outbox / inbox / 级联取消 / 交接通知全在既有事件序内）。
- **REST 管理面取消端点**：`/api/sub-tasks` 已有取消能力，不动；本批只补 Agent 工牌通道。
- **SSE 握手 query `?sessionId=`**：spring-ai 传输约定，不改（A-4 只改工具 arguments 参数名）。
- **doc/manual/executor-duty 组装手册与 ZIP skill-pack**：独立组装产物（manual-assembled.md），原登记随下一次手册组装批次同步；本批更新其唯一运行时事实源 `helloai-core/src/main/resources/onboarding/executor/guide.md`。**2026-11-17 回填收口**：用户指令「文档先正确回填吧」后同日完成——手册源 00/01/05 三章修订 + `assemble-manual.ps1` 重装（前置模板 tmp 丢失已从装配产物反推重建并增 v1.2 版本行）；executor-SKILL.md 全文镜像新口径；ZIP 定性为运行时现打包（`buildSkillPackageZip` 读 classpath，target/classes guide.md 与源逐字节一致），无需重打。遗留消除，证据见 LOG-20261117 E 段「文档回填收口」。
- **旧参数名删除**：`sessionId`/`_sessionId` 保留一个周期，删除另立批次。

### ④ 关键设计决策（自决，写明理由）

| 决策 | 取值 | 理由 |
|---|---|---|
| A-4 新参数名 | `authSessionId` | 该 ID 是 Redis 鉴权上下文键（鉴权会话），名字直述其义；与传输 sessionId、A2A contextId 均不撞 |
| 三名优先级 | `authSessionId > sessionId > _sessionId` | 新名最优；`sessionId` 是现行推荐名（guide §1.4）居次；`_sessionId` 是历史兼容名垫底（现状 `_sessionId > sessionId`，McpMcpServer:62，新序把现行推荐名提到兼容名之前，属修正而非破坏——两名同传且值不同的客户端不存在于已知接入方） |
| A-1 失败口径 | `new BizException(400, "...")` | ADR §2.6 明文「否则显式 new BizException(400, ...)」；与 startSubTask 的 reason 码模式不同是**设计授权**，非漂移。REST 入口 catch 转 R.fail、JSON-RPC 转 -32000，沿用既有异常通道 |
| A-1 终态拒绝集 | DONE / CANCELLED / DEAD_LETTER | ADR 口径「非终态」；三终态中 DEAD_LETTER 无 →CANCELLED 出边，若只拦 DONE/CANCELLED 会让 DEAD_LETTER 落到状态机通用异常（500 文案），故 MCP 协议层三态全拦、给 400 明确文案 |
| A-1 幂等语义 | 已 CANCELLED → 400（非幂等成功） | ADR 口径「非终态否则 400」；与 startSubTask 的 IN_PROGRESS 幂等不同——取消是终态操作，重复取消应显式报错而非假成功 |
| CancelSubTaskResult 形态 | `ok / subTaskId / assignedAgent(@JsonSerialize ToStringSerializer) / status / version` | 对齐 StartSubTaskResult 成功面；无 reason 字段（失败走异常）；雪花 ID 字符串序列化守 64 位精度铁律 |
| attempt 处理 | 不开新 attempt、不手动收口 | cancel 是退出不是起点；`changeStatus` 的 closeExternalAttemptOnExit 已收口 |
| CRITICAL_TOOLS | 不动（仍 3 个） | 不可关闭面刻意最小（REF-1.3b）；cancel 可被管理面关闭 |
