# HelloAI 项目基线文档

## 摘要

### 1. 文档定位

本文件是 HelloAI 当前阶段的项目基线说明，回答三个问题：

- 当前项目是什么
- 当前阶段以什么为验收边界
- 后续文档应如何分工维护

本文件不承担“逐次实施流水账”职责，也不承担“所有未来目标的完整路线图”职责。

### 2. 当前基线结论

- 当前项目是一套基于 Spring Boot + Spring AI MCP 的多 Agent 协作调度平台。
- 当前代码主线已经具备 MCP SSE 接入、鉴权、任务拉取/认领/回执/心跳、在线状态、熔断降级、Reconcile 健康检查、管理后台与基础前端页面等核心闭环。
- 当前父工程运行版本为 `spring-ai 1.1.8`，并已通过 macOS 下 `verify-mcp-auth.sh` + `verify-mcp-e2e.sh` 主链路回归。
- 当前版本的“现实基线”以代码现状、初始化脚本、验收脚本和本目录下《实现差距表》为准。
- 原《技术方案与补齐清单 v1.1》与《多类型 Agent 接入与调度可靠性开发路线图 v2.4/v2.5》保留为历史设计资产，但不再继续混写“现状 + 计划 + 实施日志”。
- 自 2026-07-10 起，涉及调度/执行链/MQ 解耦的后续设计与实现，统一优先参考《调度解耦重构分析》与 `E:\workspace\AgentTeams-main` 源码，不再沿用此前“平台内同步长链闭环”的旧方案作为主设计依据。

### 3. 文档分层规则

HelloAI 之后统一采用以下三类文档：

- 基线文档：说明项目当前边界、事实源与维护规则
- 差距表：说明“文档承诺”和“当前实现”之间的差距
- 执行记录：说明每一轮具体做了什么、影响了什么、遗留什么

调度/执行链专项设计另设：

- 调度解耦重构分析：说明 HelloAI 当前调度链为何需要向 `AgentTeams-main` 的“分发/执行/回写分层”模型收敛，以及推荐的最小迁移路径

## 细则

### 1. 当前项目边界

#### 1.1 当前已形成闭环的主能力

- MCP SSE 握手与消息链路
- 管理员 Token / Agent API Key 双通道鉴权
- MCP 工具注册与业务工具调用
- Agent 在线状态三件套：`last_seen_at` / `last_active_at` / `online_status`
- 熔断降级与同角色替代选人
- Reconcile 式健康检查与离线重分配
- Session TTL 清理
- 管理后台基础能力与前端主流程

#### 1.2 当前不作为“已完全交付”默认认定的能力

以下内容若文档中出现，默认视为“路线图目标”而非“当前仓库已完整交付”：

- 工作流模板与 Team 嵌套编排
- API Key 类 AgentExecutor 完整执行链路
- `credential_vault` 与工牌模式
- 浏览器 MCP 接入的网页版 AI
- MinIO `timeline.jsonl` 审计归档镜像
- 基于 Spring AI `ChatClient` 的平台内直调执行链路

### 2. 当前事实源优先级

发生口径冲突时，按以下优先级判定：

1. 代码与运行结果
2. Flyway 初始化脚本与数据库结构
3. 验收脚本与可复现实验结果
4. 本目录《实现差距表》
5. 本文件
6. README
7. 历史路线图/技术方案/对比文档

### 3. 当前工程红线

- JDK 固定为 `17`
- Spring AI 当前运行基线为 `1.1.8`，任何后续升级/回退都必须重新跑 MCP 鉴权与端到端回归脚本
- 后端数据库以 `helloai-start/src/main/resources/db/migration/V1__init_all.sql` 为单一初始化入口
- Controller 只做参数接收、DTO 转换与返回封装
- 出参默认走 `Response DTO`
- 代码事实与文档不一致时，优先修“文档误导”而不是掩盖实现现状

### 4. 文档职责边界

#### 4.1 本文件负责什么

- 说明当前项目基线
- 说明三类文档分工
- 说明哪些内容属于现实边界，哪些只是目标态

#### 4.2 本文件不负责什么

- 不记录每一轮具体改动细节
- 不承载逐项路线图执行进度
- 不替代差距表
- 不替代 README 的快速上手导航

### 5. 历史文档处理原则

以下文档保留，但作为历史设计资产使用：

- `doc/HelloAI_技术方案与补齐清单_v1.1.md`
- `doc/HelloAI_多类型Agent接入与调度可靠性开发路线图_v2.4.md`
- `doc/HelloAI_vs_OpenMOSS_功能对比与实现方案.md`
- `doc/HelloAI_Agent接入内容生成功能开发清单_v2.0.md`

使用原则：

- 可以引用，不再作为唯一事实源
- 发现与现状不一致时，优先更新差距表与 README
- 后续新增阶段性进展，不再继续灌入历史路线图正文
- 涉及调度/执行链结构演进时，优先以 `doc/HelloAI_调度解耦重构分析.md` 和 `E:\workspace\AgentTeams-main` 的实际源码为参考，不再以旧路线图中的同步执行链方案指导新实现
