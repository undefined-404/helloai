## 2026-09-13 McpAuthFilter 401/500 边界加固（PASS）+ 一个被证伪的旧判断

1. **背景**：批次四期间登记「`McpAuthFilter` 未收口到标准 `checkLogin`；若改，401 会变成 500」。用户要求处理该 401→500 问题。

3. **找到真正（且唯一可构造）的 401→500 路径**：`writeUnauthorized` 在 catch 块内直接 `setStatus`/`getWriter`，**未检查 `response.isCommitted()`**。当异常发生在 `filterChain.doFilter` 之后（如 `BufferedResponseWrapper.flushToUnderlying()` 已把 body 写回底层流、响应已 commit）时，强写会抛 `IllegalStateException` **从 catch 块逃出 filter** → 容器按 **500** 渲染 —— 即客户端的凭证类错误被放大成服务端错误。
4. **修复（3 项）**：
   - **`writeUnauthorized` 增加 `isCommitted()` 守卫**：已提交则放弃改写并记 warn，杜绝 `IllegalStateException` 逃逸。（核心修复）

   - **停止对外回显异常类名**：原 `"MCP 鉴权失败：" + e.getClass().getSimpleName()` 面向外部 Agent 泄漏内部实现 → 改为稳定文案，堆栈只进服务端日志。

1. **T01 依赖门禁（P0-1）**：`SubTaskServiceImpl.listAvailable` 增批量就绪过滤（`filterReady`：一次取候选集全部依赖 id 做 Set 判定，消除 N+1）；`McpToolServiceImpl.claimSubTask` 在原子认领前复用 `isReady`，未就绪返回新 reason `dependency_not_ready`。此前依赖门禁只存在于内部分发链（`dispatchPendingSubTaskAuto` / `redispatchOfflineSubTask` / `SubTaskPendingOrphanTask`），外部 Agent 通道完全旁路——本次 #8 即在前置 #4/#5/#7 尚未产出时被抢单并提交，产出必然脱节。
2. **T02 返工出口（P0-2）**：新增 MCP 工具 `startSubTask`（归属校验 + 状态白名单 ASSIGNED/REWORK/PAUSED + 已 IN_PROGRESS 幂等 + `@Transactional`），四入口注册（SSE `@Tool` / REST 别名 `/api/mcp/tools/startSubTask` / JSON-RPC `tools/call` / `TOOL_NAMES`），`DEFAULT_EXECUTOR_TOOLS` 12→13（`AgentMcpServerServiceImpl` 自动建行使存量 Agent 首次调用即启用）；`SubTaskStateMachine` 补 `REWORK→BLOCKED`（返工途中可上报阻塞）。此前 REWORK 在 Agent 通道无任何出口（`submitResult` 只自动推进 ASSIGNED、`startById` 需平台账号会话 → API Key 调 401），被驳回任务只能等人工放行。
3. **T03 结构化元数据（P1-3 + P1-4-c）**：`GetDepsSummaryResult` 增 `ready` / `notReadyCount`（与 `degraded` 正交：`ready=false && degraded=false` 即「前置未产出」；采集异常时 ready 保持 null 不表态），`DepItem` 增 `loaded` / `contentChars`；`ReviewEvidenceAssembler` 截断处输出机器可读标注行 `[TRUNCATED] file=… shown=… total=… reason=per_file_limit|total_limit`。
4. **T04 附件可发现（P1-4-b 功能性）**：`SubTaskDetail` 内联 `attachments`（`AttachmentItem`：attachmentId / fileName / fileType / mimeType / fileSize / status / loadable），经 `AttachmentService.listActive` 填充、读失败降级空列表；Agent 读附件链路打通为 `getSubTaskDetail → attachments[].attachmentId → GET /api/attachments/downloadById/{id}`（此前详情页不返回附件标识，MCP 工具面亦无附件读取）。
5. **T05 在线语义（P1-5）**：`HeartbeatServiceImpl.checkOnlineStatus` 引入 ACTIVE 值班租约作为一等存活证据（心跳过期但持租约 → 判 IDLE 而非 OFFLINE，避免在岗 Agent 被误判离线触发 `AgentHealthCheckTask` 重派其在飞任务）；用 `ObjectProvider` 懒解析 `AgentDutyLeaseService`，规避 agent 域构造器循环（Heartbeat → DutyLease → SubTask → Heartbeat）。注：`AgentSelector.isHeartbeatFresh` 本已对 WEB_BROWSER / API_KEY_LLM 豁免，故真实危害集中在 `checkOnlineStatus` 写回 OFFLINE 后的重派链。
6. **T06 核验边界 + 归属可见（P1-6 + P1-7）**：核验 Prompt 增第 11 条「不可见内容不得补全」（带 `[TRUNCATED]` 标注的附件，其不可见部分一律视为未提供证据；禁止以提交方自报数值或自检清单补全；依赖不可见内容的验收项不得判 pass）+ 截断标注说明块；`SubTaskDetail` 增 `contributors`（执行记录 ∪ 当前执行者，去重保序，`select(getAgentId)` 只取列），供「独立验证」类任务认领前自评利益冲突。
7. **T07 schema 对齐（P2-8）**：JSON-RPC `tools/list` 13 工具全量补 `required`（仅业务必填，不含服务端覆盖的 agentId/sessionId，避免旧客户端本地拒绝），`checkIn` 补 `skills` 参数，描述与实现同步。
8. **T08 租约单调（P2-10）**：`AgentDutyLeaseServiceImpl.renewLease` 到期时刻单调钳制（`max(原 expire, now+ttl)`），消除窗口随「有无在跑子任务」伸缩导致的 `leaseExpiresAt` 倒退（实测 7 分钟内回退近 3 小时）。
9. **T04b 附件读端归属授权（安全项）**：`AttachmentController` 四端点 + `SubTaskController` 时间线/对话流两端点增归属校验。**通道判定以 `_authType == "agent"` 为准**——`AuthInterceptor` 对平台账号同样写入 `_authId`（admin session id，非空），用「`_authId` 为空即平台账号」判定会把管理端全部误伤成 403；该错误前提在第二轮复审中被复现用例捕获并修正。按 §10 红线不加 `@SaCheckPermission`，以「请求属性 + 服务层归属比对」实现。
10. **T08b 文档一致性（P2-9）**：`SKILL.md` 11 处同步（返工重提四步第 2 步 `startById` → `startSubTask`、工具表新增 `startSubTask` 行、三处 12→13 工具、删除不存在的 blocked 日志 REST 承诺、补 `dependency_not_ready` / `ready` / `loaded` / `attachments` / `contributors` 说明、补「附件正文仅可读本人名下子任务 + 上游前置用 `getDepsSummary`.deps[].content」）；`doc/manual/executor-duty/` 六章同步（`startById` 全量改向 `startSubTask` 并保留「该端点 401」警示、工具清单补 `startSubTask` 与新字段、13 工具计数、405 语义行改为 401 通道行），经 `assemble-manual.ps1` 重装生成 `manual-assembled.md`（58079 字符）。
