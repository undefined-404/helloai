## LOG-20260901-001 Planner Chat 输入优化（PromptEnhancer，关闭 Gap N-011）

### 背景

用户在 Planner Chat 输入需求时，常出现表达松散、约束不明确、关键信息缺失的情况。需要在发送前提供"一键优化输入"能力，把原始输入改写为更清晰、结构化、适合 Planner / Agent 理解的 Prompt。

对应实现差距表旧编号 `N-011 Planner 输入优化`（TODO → DONE，已从当前差距表移除）。

### 问题

- 输入优化能力不存在，用户只能手工组织需求描述；
- 现有 LLM 调用链路（`AgentChatClientService` → Spring AI ChatClient）全链路没有 temperature 入口，无法按"低温度、高保真"要求调用模型。

### 决策

1. **独立能力，不进 Planner 主流程**：新建独立 `PromptEnhancer` 服务，只做"当前输入 → LLM → 优化输入"，禁止连接 MCP / 数据库 / 任务执行；不修改 CHAT / CLARIFY / 拆解任何既有链路。
2. **复用现有 LLM 抽象**：模型选型走 `PlannerAgentPicker.pick(null)` 自动选择（与澄清链一致），执行走 `PlatformAgentExecutionService.executeSync`，不新建第二套 LLM 框架。
3. **temperature 增量打通**：`AgentTask` 增加可选 `temperature` 字段（`null` = 模型默认），仅同步路径由 `ApiKeyAgentExecutor` 透传 → `AgentChatClientService` 6 参重载 → `ChatOptions.builder().temperature()` 注入。现有调用方零行为影响，流式路径不动。
4. **语义保护写进 System Prompt**：独立模板 `prompts/prompt-enhance.md`，核心原则"增强表达，而不是重新定义需求"，明确不改用户指定的字段名 / 接口名 / 数值 / 实体 / 工具名，不虚构表 / 字段 / 接口 / 路径，信息不足保留"待确认"。
5. **前端只回填不发送**：优化结果进入预览面板，用户可"重新优化 / 使用此版本 / 关闭"，使用此版本仅回填输入框，不自动发送、不覆盖原始输入。

### 实现

后端（helloai-common / helloai-core / helloai-api / helloai-start）：

- 新增 `core/planner/prompt` 包：`PromptEnhancerService` / `impl/PromptEnhancerServiceImpl` / `PromptEnhanceResult`
- 新增 `prompts/prompt-enhance.md` System Prompt 模板
- 新增 `PromptEnhancerProperties`（`helloai.planner.prompt-enhance`：enabled + temperature 默认 0.2）
- 新增 `POST /api/planner/prompt/enhance`（Request `{prompt}`，Response `originalPrompt + optimizedPrompt`），复用 `AuthInterceptor` 鉴权与 `R` 统一响应
- 修改 `AgentTask` / `ApiKeyAgentExecutor` / `AgentChatClientService(+Impl)` 打通可选 temperature

前端（helloai-ui）：

- `RequirementChat.vue` 输入区增加「优化输入」按钮与预览面板
- 新增 `api/promptEnhance.ts`（120s 超时）、`paths.ts` 收口 `/planner/prompt/enhance`、`dtos.ts` 类型

### 验证

- `PromptEnhancerServiceTest` 5 用例（成功路径 / disabled / 空输入 / LLM 失败 / 空输出）+ 既有 `AgentChatClientServiceTest` 2 用例全绿
- `mvn -pl helloai-start -am compile` 通过
- `npm run type-check` 0 error
- 真实环境端到端冒烟留待人工确认

### 结果

输入优化第一版交付，Gap N-011 关闭。明确的第一版边界：

- 不携带会话上下文（只优化当前输入）；
- 优化结果不自动发送；
- 流式执行路径暂不支持 temperature；
- 选型走自动选择，不跟随会话钉住的规划者。

### 影响

既有 CHAT / CLARIFY / 拆解 / MCP / Task DAG 链路零改动；`AgentTask.temperature` 为可选字段，所有现有调用方行为不变。

## LOG-20260901-002 生产两问题：澄清会话终稿确认丢失更新竞态修复 + 超时改派时间线可观测（关闭线上问题）

### 背景

生产环境部署测试发现两个问题：① 任务拆解分发后，澄清会话仍显示「进行中」、「创建任务并自动拆解」按钮仍在，再次点击报错；② 子任务超时未完成 / 超时未领取触发自动重分派时，这两个关键调度节点没有记录到执行时间线，用户无法直观感受调度流程。

### 问题

- **问题1（丢失更新竞态）**：`finalize()` 把会话置 `FINALIZED` 后，CLARIFY 轮末的全字段 `updateById` 用长窗口（LLM 轮）前的陈旧快照覆盖，状态回退 `ACTIVE`；且无幂等防御，重复点击可重复建任务。
- **问题2（调度节点不可观测）**：「超时未领取改派」（`AssignedSubTaskTimeoutTask` → `redispatchAssignedTimeout`）只有被精简时间线隐藏的通用 `sub_task_dispatch_prepare`；「执行超时改派」（`ExecutionCompensationTask` RUNNING 超时）只有通用 `sub_task_execute_failed`，无专属超时事件。

### 决策

1. **状态推进用 CAS + 幂等防御**（CODE_STYLE §13 先校验再修改）：`finalize` 改为 `lambdaUpdate().eq(status, ACTIVE).set(status, FINALIZED)` CAS 推进，失败抛「会话状态已变化」；已关联存活任务时拒绝重复创建。
2. **长窗口后写库改定点更新**（§14 / §2.2 最小改动）：终稿字段与 `task_id` 回填全部改 `lambdaUpdate()` 定点写，消除全字段 `updateById` 的陈旧快照覆盖面；手动确认与 `/task` 直达提取共用段 `finalizeAfterDraft`（§50.4 优先复用），两路径共享幂等 + CAS 语义。
3. **前端并发守卫**：「创建任务并自动拆解 / 重新生成终稿」按钮 `:disabled="sending || finalizing"` + 函数头部守卫，双保险防重复提交。
4. **超时改派补专属可观测事件**（不加新链路、不动调度逻辑，仅留痕）：两个检测节点各记一条专属时间线事件；`ExecutionCompensationTask` 的时间线写入 try/catch 包裹，不阻断补偿主链路。
5. **数据修复交给用户执行**（MCP 只读 + 生产库不可达）：交付修复 SQL，不在代码侧自动改数。

### 实现

后端（helloai-core / helloai-job）：

- `RequirementClarifyServiceImpl`：`finalizeAfterDraft` 共用段（幂等校验 + `casFinalize` CAS + 建任务）；`updateFinalDraftFields` 定点写；`task_id` 回填定点写；手动确认与 `/task` 直达共用同一入口（timeline 事件区分 `task_created_from_clarify` / `task_created_from_clarify_direct`）
- `SubTaskDispatchServiceImpl.redispatchAssignedTimeout`：新增 `sub_task_unclaimed_timeout_reassign` 事件（payload: previousAgentId / role），保留原 `sub_task_dispatch_prepare(trigger=assigned_timeout)`
- `ExecutionCompensationTask`：新增 `TaskTimelineService` 依赖；RUNNING 超时且子任务仍 IN_PROGRESS 时，在 `handleFailure` 前记 `sub_task_execution_timeout_reassign`（payload: previousAgentId / timeoutMinutes / eventId，空值防御）

前端（helloai-ui）：

- `RequirementChat.vue`：finalize / regenerate 并发发送守卫 + 按钮禁用
- `SubTaskDetail.vue`：`EVENT_META` 补两个超时改派事件（标签 + 一句话描述）；`eventTypeColor` 含 `timeout` 归 warning；`eventCategory` 含 `timeout_reassign` 归「分发」；两事件不在 `COMPACT_HIDDEN_EVENTS`，精简模式默认可见（解决用户看不到的问题）

### 验证

## LOG-20260902-001 Phase 0 A1/A2：Run/Turn/Step 模型定稿 + 状态机加固（CAS + Lease + Watchdog + Reconciler）

### 背景

架构改造长期思路 P0（Event Stream → 双轨 Executor → AgentRuntime 抽象）启动。本轮先落两件事：① 用 ADR 定稿 Run/Turn/Step 执行模型（后续事件流的语义锚点）；② 状态机加固——为「Agent 崩溃 / 宕机后 IN_PROGRESS 子任务无人接管」补齐 CAS + Lease + Watchdog + Reconciler 四件套，把回收粒度从「分钟级超时巡检」细化到「租约到期」。

### 决策

1. **ADR-001 定稿执行模型**：Run = 一次需求完整执行（task + round 派生 run_id）；Turn = 一次 Agent 完整工作周期（sub_task 每次执行尝试）；Step = Turn 内原子动作（append-only）。落地约束：Phase 0 不建 plan 实体、不迁移执行表、只做后续事件流的口径依据。
2. **租约机制**：sub_task 进入 IN_PROGRESS 时写 owner + lease_until（now + ttl）；Watchdog 每节点独立续自己 owner 的租约（ShedLock 豁免，与 Reconciler 集群单例相反）；Reconciler 集群单例扫描过期租约 CAS 回收为 PENDING 重派，写 task_timeline 回收事件。
3. **Watchdog 开关**：helloai.agent.watchdog.enabled（默认 true），关闭时 changeStatus 不写租约、完全回归存量行为。
4. **存量数据边界**：V63 前存量 IN_PROGRESS 行 owner/lease_until 为 NULL，不受租约机制管理，继续走既有超时巡检路径。
5. **mark* CAS 改造**：AgentExecutionRecord 加 @Version；markRunning/markSuccess/markFailed/markTimeout 由 lambdaUpdate 链式改为 update(entity, wrapper) + eq(status, oldStatus) 双条件（链式不触发 MP 乐观锁拦截器，规范 §15）。

### 实现

- 新增 doc/design/adr/ADR-001-run-turn-step-model.md（A1 产出）
- V62__agent_execution_record_add_version.sql：agent_execution_record 加 version（ADD COLUMN IF NOT EXISTS 幂等风格）
- V63__sub_task_add_lease.sql：sub_task 加 owner / lease_until + 部分索引 idx_sub_task_lease_expiry
- AgentExecutionRecord 加 @Version；SubTask 加 owner / leaseUntil
- AgentExecutionRecordServiceImpl：mark* 四方法改 update(entity, wrapper) CAS；getHostName 提取为 common/util/HostNameUtils（与 sub_task.owner 同源）
- SubTaskServiceImpl：changeStatus 进 IN_PROGRESS 写租约；新增 renewCurrentNodeLeases（按 owner 续期）与 reclaimExpiredLeases（扫描过期回收，显式走 SubTaskStateMachine.validate）
- SubTaskStateMachine：补充 IN_PROGRESS → PENDING（仅租约回收路径，注释标注语义边界）
- 新增 common/config/WatchdogProperties（helloai.agent.watchdog：enabled / ttl-seconds=300 / renew-interval-seconds=150）
- 新增 helloai-job：WatchdogLeaseRenewTask（每节点独立、无 ShedLock、@ConditionalOnProperty）+ LeaseReconcilerTask（ShedLock 集群单例，DutyLeaseExpirationTask 同构）
