## LOG-20261101-002 SKX-9 平台级 sha256 三方对账 补收口（待核→已核）

#### 背景

`SKX-9` 按用户裁定通过后，**平台级 sha256 三方对账仍为待核**——SKX-9 原计划第 3 步「`readArtifact` 回读比对三方」

sha256，与 deliver/check 回执的 `artifact.sha256` 比对。此即「对已物化附件独立回读」路径，无需重跑 7058→7059→7060 全链。

## LOG-20261102-002 G-026 LLM 额度与用量监控 M1 实施（Q-1~Q-9）

#### 背景

平台同时接入 4 家外部供应商（DeepSeek / Moonshot / MiniMax / 博查），余额分散在各自控制台，平台侧此前只能靠「调用失败」事后感知额度耗尽（差距表 `G-026`）。用户裁定「可以进行着手开发了」，按 `plan/HelloAI 额度与用量监控实施计划（2026-11-02）.md` 依次执行 `Q-1`~`Q-9`。

#### 问题

1. 余额无平台入口、密钥零散（3 家 LLM 在 vault、博查在 sys_config）、无快照/缓存/定时采集，多实例会重复打外部接口。
2. MiniMax 是额度型（百分比）而非金额，若强行换算会伪报；失败若回填 0 会误导「没钱了」。
3. 通义千问无公开余额接口，需 AK/SK 签名，而平台只有 `sk-` key。

#### 决策

- **单表快照**：只建 `llm_balance_snapshot`（不建 account / usage_daily，避免与 vault、事件源双写漂移）；`quota` 归 `system` 域，不新建 Maven module。
- **SPI + 双层密钥抽象**：`BalanceProvider(key/supports/fetch)`，`fetch` 不抛异常、失败返回 `failed(reason)`；密钥按 provider 路由——deepseek/moonshot/minimax 走 vault，博查走 sys_config。跨域复用走**端口反转**：`system.port.PlatformApiKeyPort` / `WebSearchApiKeyPort` 由 `system`（消费方、低层）定义，`agent` / `planner` 各自提供 adapter 实现，保持 `system` 不反向依赖上游（§6 / §7.2）。
- **缓存与熔断**：Redis RBucket 成功 60s / 失败 30s + Resilience4j `quotaFetch`；前端 30s 可见轮询、定时采集 15min；不采用 SSE。
- **收口装配**：新增 `QuotaConfig` 显式装配 4 provider + 有序注册表；`BalanceQueryService` 线程池补 `@PreDestroy`。
- **开关**：`sys_config["quota.widget.enabled"]` 平台开关 + `quota:view` 权限双闸门；另设 `GET /api/admin/quota/widget-enabled`（`quota:view` 保护），避免依赖未绑 ADMIN 的 `config:view`。

## LOG-20261102-003 G-026 UX-1 刷新间隔可配 + 浮球纵向拖拽修复

#### 背景

`LOG-20261102-002` 交付后，用户确认「额度监控没问题」，同时提出三点：① 刷新频率是否 1 分钟一次、是否浪费 token；② 刷新频率能否放进「系统设置—平台设置」（1 分钟~1 小时自定义，或不自动刷新只手动点）；③ 浮球只能左右移动、无法上下移动。

#### 问题

1. **节奏写死**：前端固定 30s 轮询、后端成功缓存 60s、定时采集固定 15min；用户无法按环境（演示/生产/无网）调整请求频率。
2. **成本认知缺口**：「余额刷新会不会烧 token」没有在代码与文档里给出事实口径。
3. **纵向拖拽方向反转**：`positionStyle` 用 `bottom` 定位，`onPointerMove` 却写成 `dragStart.py + dy`。从默认右下角向上拖时 `bottom` 立即收敛到最小值，表现为「只能左右移动」。

#### 决策

- **一个配置键统管自动刷新**：`sys_config["quota.refresh.interval-seconds"]`，`0`=仅手动、`60~3600`=自动间隔、空/非法回退 `60`。前端轮询、手动模式、定时采集共用这一口径，禁止第二套节奏定义。
- **手动模式也不假装新鲜**：新增 `GET /overview?fresh=false` 只读最近落库快照，打开面板不触网；用户显式点「刷新」才请求外部接口。
- **定时采集服从间隔**：手动模式不抓；自动模式逐家判断「最近快照是否已晚于间隔」，避免手动刷新单家导致其余家被饿死。
- **不改 yml**：`helloai.quota.collect-interval-ms` 仍是任务基础节拍（15min），sys_config 是用户可见的**最小抓取间隔**；两者取更保守的一侧。

#### 实现

- 后端：`QuotaWidgetSettings`（配置键 + 归一化纯函数）；`QuotaController` 的 `/widget-enabled` 升级为 `/widget-config`（开关 + 间隔），`/overview` 增加 `fresh` 参数；`BalanceQueryService.cachedOverview()` / `allProvidersCollectedSince()`；`BalanceCollectTask` 手动模式跳过抓取（清理照跑）、按间隔跳过；`QuotaProperties` Javadoc 对齐。
- 迁移：`V131__quota_refresh_interval.sql`（`partial unique index` 幂等种子，默认 `60`）。
- 前端：`Settings.vue` 新增「4 额度监控」区（浮球开关 + 自动刷新开关 + 1~60 分钟间隔，保存走 `batchUpdateConfig`）；`QuotaFloatWidget.vue` 按配置动态轮询、手动模式只读快照、`dragStart.py - dy` 修正纵向方向、「最后更新」取快照抓取时刻并用 30s 时钟刷新相对时间；`api/quota.ts` / `paths.ts` 同步。

#### 验证

- **单测**：`QuotaWidgetSettingsTest` 5 例 + `BalanceQueryServiceTest` 新增 4 例（cachedOverview 不触网 / 无历史 / 失败态 / 逐家近期判断）；quota 用例 **45 例全绿**；`helloai-core` 全量 **2862 例 0 失败**、`BUILD SUCCESS`。
- **构建/守卫**：后端全模块编译通过；前端 `npm run build` 通过；`check-arch-freeze.sh` 全绿（组 1/组 2 违规 0；`api->core.entity` 58 与 HEAD 一致，本次未新增；基线未改动）；`verify-plan-status.sh` 全绿（`Q-10` 状态齐备）。
- **事实口径**：4 家余额接口均为账户查询端点，不经过模型推理，**不消耗 LLM Token**；改造前页面打开时外部请求约 1 次/分钟（30s 轮询 + 60s 缓存），改造后默认同为 60s，可调到 1 小时或仅手动。

#### 结果

- 系统设置可调刷新节奏；手动模式打开面板零外部请求，符合「不刷新只手动点」的诉求；浮球四向可拖。
- 计划 `Q-10` 已完成；差距表 `G-026` 状态由「验证中」转「已完成」（用户可视化验收通过）。

- **PA-2 双轨分层**：`requirement_message` 为真相源，`long_term_memory` 为精选子集，`user_profile` 为结构化画像；规则抽取打底并保留 LLM 接口，每轮异步触发，合并时列表并集 + 字段覆盖 + 版本自增。
- **PA-3 单助理展示**：`assistant_profile` 只承载当前助理身份卡，不做人格市场。
- **PA-4 右栏三段 + 独立菜单**：工作台右栏固定三段（任务概况轮播 / 最近任务 / 最近产物），块内各自滚动；「任务概况」第一屏 2×2 计数、第二屏活跃 Agent（内/外圆形徽标）；旧「对话新建」入口产物面板逻辑不变。
- **PA-5 产物三源聚合**：会话产物 / 执行产物 / 附件统一为 `ArtifactItemVO`，按会话单源去重后供右栏与 `/myArtifacts` 使用。
- **PA-6 进程内事件 Hub**：`WorkbenchEventHub` + SSE `/workbench/stream`，任务事件只推提示，前端收到后重拉聚合，不新造事件内核；单副本前提已登记。
- **PA-7 复用 G-026**：额度浮球由 `MainLayout` 全局挂载，助理入口天然可见，不新增成本链路。
- **迁移版本不新增**：V132 / V133 / V134 均为未提交新迁移，按用户要求直接在既有未提交版本上就地调整；V134 菜单 `hidden=1`（路由仍注册可达），本机菜单由人工调整。
