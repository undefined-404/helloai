## LOG-20261101 SKX-9 用户裁定通过回填 + SKX-10 事实登记与文档回填 + SKX-15 部署面用户自测回填

#### 背景

`SKX-9` 端到端验收的**核心证实目标「模型在工具循环里自主触发 `internal_run_skill`」已于真机验真**，但 C1 档
判据③「外链 grep=0」与 archify 出厂模板 `assets/template.html` 硬编码的 1 条 GitHub 署名 `href` 冲突——
全包无 `--no-credit` 开关，唯一出路是改模板、而改模板即破坏 `provenance=current` 与「出厂包可复现」，
非执行者边界内可解，子任务因此 7059 三次 rework 后 `DEAD_LETTER`（rework_limit_exceeded）、7060 PENDING。
这段裁决缺口此前一直悬置（见 `review/HelloAI SKX-9 端到端验收记录（2026-11-01）.md` §5）。

`SKX-10`（事实登记与文档回填）与 `SKX-15`（部署面收口）因 SKX-9 未定性而被搁置；`SKX-15` 部署面剩余三条
（`start.sh --with-sandbox` 实测 / `.ps1` 脚本 / 云安全组 40000-60000 段核实）需服务器环境验证，本机 4 GB
不满足 5.5 GB 门槛。

#### 问题

2. `SKX-10`「事实登记与文档回填」的动作项在 SKX-9 未有结论前无法填入「已验事实」。

#### 决策

1. **判据③（用户裁定 2026-11-01）**：archify 用的是 GitHub 开源项目，**保留署名、不撤链接**；离线 HTML 已自包含
   （加载型资源全内联 data:，唯一外链 `href` 是 GitHub 署名超链接、不影响双击离线浏览）；**不给 archify 增加
   `--no-credit` 开关**；`SKX-9` **按通过**回填——此系**裁决式通过**，不是「自动化检查通过」。
2. **`G-005` 条件② 已命中**：SKX-9 真机模型在工具循环自主触发 `internal_run_skill` 于开沙箱容器内执行 ⇒
   触发条件②「技能包被执行」成立；条件①「平台增加碰宿主工具」（容器内 `filesystem=ISOLATED`、「碰宿主」不成立）
   与条件③「平台自持浏览器」（C1 先行不装 Chromium）仍不命中。`G-005` 行状态由「暂缓」改判「暂缓（条件②已命中，重排期待议）」。
3. **`SKX-15` 部署面剩余三条（用户自测）**：用户在 39 服务器自测 `--with-sandbox` / `.ps1` / 云安全组端口段核实，
   **效果无问题**，回填「用户自行测试，没问题即可」。
4. **平台级 sha256 三方对账**：仍为**待核**（7060 因上游死信未分发），不影响技能通过判定，如实标注。

## LOG-20261101-002 SKX-9 平台级 sha256 三方对账 补收口（待核→已核）

#### 背景

`SKX-9` 按用户裁定通过后，**平台级 sha256 三方对账仍为待核**——SKX-9 原计划第 3 步「`readArtifact` 回读比对三方」
本应由子任务 7060「导出 HTML 为可下载附件并与回执哈希对账」承载，因上游 7059 死信（非 DONE）7060 保持 PENDING
未分发，平台级独立回读缺验（验收记录 §2.4 / §5.1 原如实标注「待核」）。本 LOG 记录该口子的补收口。

#### 问题

平台侧未独立回读产物字节，三条口径（回读 sha256 ↔ 回执 `artifact.sha256` ↔ 文件实际字节）的「平台级一致」未经核对，
是 `SKX-x` 专项唯一没关实的待核项。

#### 决策

对已物化的平台产物对象做**平台对象层独立回读**（不从沙箱、不依赖 7060 分发）即可关闭该项：直接
`get_object` 平台附属件（MinIO `helloai-artifacts`）中 `2116760891167277059` 子任务名下的最终交付产物，计算
sha256，与 deliver/check 回执的 `artifact.sha256` 比对。此即「对已物化附件独立回读」路径，无需重跑 7058→7059→7060 全链。

#### 实现

- 本地 `E:\python3.14` 无 minio/boto3 客户端，暂无可复用下载通道。临时 `python -m pip install minio` 装入该解释器
  （minio 7.2.20，安装路径为本机 Python 环境，不改仓库、不新增项目依赖），写一次性回读脚本 `get_object` 下载并哈希。

  （attachment 2116765045931573250，file_size 820084，即验收记录 §2.3 的 820,084 B 最终交付产物）。

  bytes 820084，receiptId `cff77463…`，与 check 回执 `deliveryReceiptId` 一致）、check 回执 `943cf3ba-check-receipt.json`
