## 平台技能规范（任务所需技能命中 eng-* 规范）
> 以下规范由平台按任务 required_skills 命中注入；产出必须按此执行，审查侧按同一清单核验。

### eng-code-review
> 来源：提炼自 DeepSeek Harness `dsh-code-review`，已按 HelloAI 语义适配（2026-08-20，§6.114）。
> 定位：本规范同时约束执行侧（按此纪律自查产出）与审查侧（`prompts/subtask-review.md` 轨道 B 按同一清单核验），双方共用同一词汇表，形成「执行侧产出 / 审查侧解析」闭环。

## 执行速览（任务 required_skills 命中 eng-code-review 时注入执行 Prompt）

1. **接口契约（C1）**：对外接口必须文档化——函数签名、返回值区分（错误 / 空 / 正常三种语义不混用）、异常约定（抛什么、谁处理）、边界条件（空输入 / 超限 / 并发 / 超时）。任何「调用方须知」不得靠口头约定，必须写进文档或注释。
2. **生命周期与并发（C2）**：资源创建与释放成对出现（文件 / 连接 / 锁 / 线程池），无可观测泄漏；涉及共享状态时说明锁粒度与竞态处理；异步任务必须定义取消路径与错误上报路径。
3. **验证强度（C3）**：每个关键行为至少一条真断言——删除或改写该断言会因目标回归而失败；禁止「永真」冒烟断言充当验证证据。
4. **范围与必要性（C4）**：不写投机泛化与过度抽象；新增依赖须说明必要性；能复用标准库 / 既有组件的不手写。
5. **自查产出格式**：自查发现的问题按四元组记录 `[defect] 缺陷描述 [location] 位置（文件名 / 行号 / 字段名） [impact] 影响 [evidence] 依据`，修复后随产出更新。

### eng-verification
> 来源：提炼自 DeepSeek Harness `dsh-pre-push-checks`，与 HelloAI VERIFICATION 围栏对齐（2026-08-20，§6.114）。
> 定位：约束执行侧交付物的验证证据——什么算「验证过」、证据怎么记录；审查侧 `prompts/subtask-review.md` 轨道 B 的 C3 验证强度与本规范同源。

## 执行速览（任务 required_skills 命中 eng-verification 时注入执行 Prompt）

1. **最小证据集**：按改动范围选择能证明「目标行为正确 + 无回归」的最小验证组合——编译 / 单测 / 验证脚本 / E2E 不必全上，但所选组合必须覆盖目标行为本身。
2. **证据真实可复现**：交付时写明验证命令、实测输出关键片段、通过 / 失败结论；不得用「已验证」「测试通过」的叙述代替证据。
3. **断言有效性**：验证断言必须因目标回归而失败（与 eng-code-review C3 同源）——写死预期、跳过断言等于无验证。
4. **环境可复现**：注明验证环境（JDK 版本 / 服务版本 / profile / 关键配置）；脚本类验证须遵循项目 UTF-8 编码规则，输出可读。
