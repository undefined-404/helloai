## 验收标准（逐条核验；任一条不达标即为驳回 pass=false）

1. **覆盖追溯完整**：报告为每一个有产出的已完成子任务的主题提供了归属（覆盖追溯表或正文章节），不存在"有子任务但报告完全未提及/未归属"的情况；章节编号与覆盖追溯表一一对应。
2. **跨章重复率**：同一契约性事实（表格/代码/参数/阈值/路径）未完整重复出现在多个章节；**同一组 ≥4 行的内容块（如风险清单、参数表、结论组）不得在 2 个及以上章节逐字重复**；允许"详见 §X"式引用交叉，正文无大段重复。命中逐字重复即不达标。
3. **表格/代码块完整性 + 无空壳引用**：迁移自子任务产出的 Markdown 表格保持全部行列、代码块保持全部参数与注释（围栏 ` ``` ` 成对闭合）；**报告正文中不得出现「见分册 / 详见子任务X / 详见附件 / 详见前文 / 不再赘述」等把契约性事实外置的表述**——凡出现即不达标（契约性事实必须在本报告中完整可见）。
   - 注：报告在送交你之前**已过一道确定性机械校验**——上述"空壳引用""围栏失衡"若命中已直接驳回、不会送到你这里；你仍须独立复核第 1、2、4、5 条。
4. **主线成立**：执行摘要开头的结论（主线论点）与正文事实一致，不存在正文不支持或与正文矛盾的摘要结论。
5. **无证据外提炼**：报告未包含子任务产出证据之外的"新事实/新数据/新结论"（对证据的合理归纳与措辞整合允许；**新增具体事实/数值/决策/结论不允许**，出现即视为无出处提炼）。
6. **叙事预算自洽**：篇幅约束针对**叙事性文字**（概述/衔接/铺垫），**不适用于契约性事实**——若报告为凑预算而裁剪表格行列、省略清单项或外置事实，即不达标；反之，报告叙事偏长但事实完整，不构成驳回理由。

## 输出格式（严格遵守）

只输出一个 JSON 对象，不要输出任何解释、前后缀或 Markdown 代码块标记：

```json
{
  "pass": true,
  "score": 4,
  "issues": "",
  "comment": "一句话核验结论",
  "missingEvidence": [],
  "analysis": "逐条对照 5 条验收标准的核验分析过程"
}
```

- `pass` 为布尔值；`score` 为 1~5 整数（pass=true 时不低于 3）。
- 不通过（pass=false）时 `issues` **必填**：按验收标准编号（1-6）逐条列出不达标项与具体修正建议，可直接指导返工重写。
- `missingEvidence` 为数组（可为空）；`analysis` 必填，逐条写明每条验收标准通过/不通过的理由与依据（引用报告或证据原文）。
