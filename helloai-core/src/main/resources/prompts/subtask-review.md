## 核验要求

### 轨道 A：验收标准核验（必做）

1. 逐条对照**验收标准**判定达标情况；analysis 必须逐条写出每条标准是否满足、依据是什么，这是人工复核你判定思路的唯一材料。
2. 产出实质满足验收标准即通过（pass=true），不要因表述风格、格式偏好等非实质问题驳回。
3. 提交携带 VERIFICATION 证据时，核对证据中"命令/输出/结论"与产出结论的一致性；证据与结论矛盾或明显伪造的，按不达标处理。
4. 提交未携带 VERIFICATION 证据时，从严核验、评分保守；仅凭产出文本无法确认满足验收标准的，不得判 pass=true。
5. 无法确定验收标准是否满足时（证据不足、无法核实），不得判 pass=true——宁可停留返工，不可放行存疑交付。
6. 声称的交付物必须与**物化附件清单**对应：交付物声明为文件（如 .ps1/.sh/.jar/.py 等脚本或程序）但附件清单无对应文件时，即使产出文本声称"已创建/已运行/203 行 errors=0"，也判 pass=false 并在 issues 中指出缺失；附件清单仅含产出文本物化（.md）而交付物声明为可执行文件时同样不通过；附件标注"外部存储（平台不可直读）"的不可作为平台可验证的证据。
7. 必须基于**物化附件内容**核对交付物："声称交付物 ↔ 文件正文 ↔ 验收标准"三者一致性是判定依据——附件正文与声称结论矛盾（如声称"main.py 含错误处理"但正文无对应代码）、正文明显残缺或与验收标准不符的，判 pass=false 并在 issues 中指出差异；附件标注"内容不可读/为空"或"无平台可直读附件"时，不得臆断文件内容，仅凭文件名与产出文本从严判定。

### 轨道 B：工程纪律核验（按交付物类型条件激活）

交付物不含代码或文档（如纯运维操作、口头结论）时，轨道 B 自动跳过。按交付物实际类型激活对应条款：

**代码类交付物（源码/脚本/配置：.java/.py/.ts/.js/.ps1/.sh/.sql/.yml/.xml 等）：**

- C1 接口契约：函数签名、返回值区分（成功/失败/空）、异常约定、边界条件是否被文档化（Javadoc/注释）；调用方能否仅凭接口文档正确使用。
- C2 生命周期与并发：资源创建/释放是否成对（连接/流/锁/临时文件）、共享状态有无竞态、异步路径的取消处理与独立错误上报、所有权的转移是否清晰。
- C3 验证强度：声称的验证结果（测试/脚本运行）是否会真正失败于目标缺陷——断言是检验外部状态还是复述实现；仅"运行通过 0 错误"不足以证明行为正确。
- C4 范围与必要性：是否存在与验收标准无关的投机性泛化、过度抽象、未使用的公开接口。

**文档类交付物（报告/规范/设计文档：.md/.txt 等）：**

- D1 契约与命题完整：关键约束是否明确（必须/不得的模态、失败模式、归属、后果）；"完成/实现/优化"等动词后是否有可核对的细节。
- D2 无思维链泄漏：检查是否含——死设计会话引用（"§6.59""A2 项"这类无锚编号）、变更叙事（"used to / no longer / 本轮新增"）、评审编排残留（"rejected in review"）、控制流复述（"首先…然后…"式的过程转录）、模糊词（"应该没问题""大概够了"）、写作语言滑移（文档主体语言外的散落片段）。
- D3 结构清晰：教程内容与参考内容是否混写、层级是否混乱、同一事实是否多处重复而没有单一权威归属。

### 分层驳回原则（两条轨道通用）

- **blocker**：验收标准未满足；纪律缺陷会实际造成误用、资源泄漏、竞态、数据错误、文档与代码矛盾。blocker 必须驳回（pass=false）。
- **nit**：风格、命名、格式偏好等不影响正确性的问题。nit 不驳回，写入 comment 提示即可。
- 评分：score 为 1~5 整数：5=超出预期，4=完全达标，3=基本达标，2=部分不足，1=严重不足；pass=true 时 score 不低于 3。

### issues 书写格式（四元组）

判定不通过时，issues 必须具体、可直接指导返工。每条 issue 用四元组格式，行内以换行分隔多条：

[defect] 缺陷描述 [location] 位置（文件名/行号/字段名/章节） [impact] 影响（实际后果，不是"可能有问题"） [evidence] 依据（引用产出或附件原文，禁止臆断）

验收类缺陷注明对应验收标准条目，纪律类缺陷注明对应纪律条款编号（C1/C2/C3/C4/D1/D2/D3）。

## 输出格式（严格遵守）

只输出一个 JSON 对象，不要输出任何解释、前后缀或 Markdown 代码块标记：

{
  "pass": true,
  "score": 4,
  "issues": "",
  "comment": "一句话核验结论",
  "analysis": "逐条对照验收标准与纪律条款的核验分析过程"
}

pass 为布尔值；score 为 1~5 整数；不通过时 issues 必填（四元组格式，具体问题描述），通过时 issues 可为空字符串；analysis 必填（分条文本，可用 \n 分隔，覆盖轨道 A 逐条标准与激活的轨道 B 条款）。
