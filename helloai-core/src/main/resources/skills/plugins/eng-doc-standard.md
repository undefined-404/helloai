# eng-doc-standard 平台文档规范

> 来源：提炼自 DeepSeek Harness `dsh-prose-standard` / `dsh-doc-standards`，已按 HelloAI 语义适配（2026-08-20，§6.114）。
> 定位：约束执行侧交付的文档类产出（说明 / 报告 / 手册 / 注释文档），审查侧 `prompts/subtask-review.md` 轨道 B 文档类 D1-D3 按同一清单核验。

## 执行速览（任务 required_skills 命中 eng-doc-standard 时注入执行 Prompt）

1. **命题完整保留（D1）**：每条「必须 / 不得」的陈述必须含 主体 + 条件 + 模态 + 失败模式——谁、在什么条件下、必须/不得做什么、做不到会怎样。契约性事实（表格 / 代码 / 参数 / 阈值 / 路径 / 状态码）必须原样保留，不得因行文精简而丢失。
2. **tutorial / reference 分离（D3）**：操作步骤（how-to）与概念参考（reference）分节组织，不混写——教程按用户旅程组织，参考按主题词条组织。
3. **无思维链泄漏（D2）**：文档不得出现实现过程叙事（「我们先试了 X 不行改 Y」）、版本戳、设计会话引用、评审编排残留等 8 类泄漏（速查见详细规范）。
4. **信息密度**：删「文档废话」——无信息量的铺垫、重复句、免责声明堆砌；同一结论不重复出现。

---

## 详细规范

### 命题完整保留

- 命题模板：`在 {条件} 下，{主体} {必须/不得} {行为}；{做不到的后果/降级行为}`。
- 检查清单：每条约束是否有归属（谁负责）、是否有触发条件、是否有失败模式。
- 反面示例：「错误会返回」——缺谁返回、什么错误、调用方怎么感知。
- 正面示例：「配置缺失时，服务启动失败并输出 `missing api key` 错误日志，健康检查返回 503」。

### tutorial / reference 分离

- tutorial（教程）：按用户旅程组织（准备 → 第一步 → 验证 → 常见问题），允许步骤重复、允许显式提示「仅演示用」。
- reference（参考）：按主题词条组织（每个词条 = 概念 + 契约 + 边界），无顺序依赖。
- 混写症状：教程里插大段概念解释、参考里夹杂「接下来我们…」的操作叙事。

### 思维链泄漏 8 类速查

1. 死设计会话引用：「在上一轮讨论中我们决定…」
2. 变更叙事：「从 V1 改为 V2」「先把 X 迁到 Y」
3. 实现过程叙事：「先尝试了 A 方案，遇到 B 问题，改用 C」
4. 评审编排残留：「通过评审后…」「按照审查意见修改了…」
5. 版本戳：`（V39）`、`2026-08 起`、`（第 2 版，重要）`
6. 元讨论：「文档本身应包含 X 节」「此处该不该写 Y」
7. 占位符 / 模板残留：「TODO」「XXX」「待补充」
8. 多轮迭代痕迹：「首轮」「每轮对话」「上一轮」等轮次叙事

保留原则：以上内容只允许出现在项目内部的迭代执行记录 / 变更日志里，不得出现在面向使用者的文档正文中。

### 信息密度

- 删除标准：删掉一句话后文档信息不减少，则必须删。
- 保留标准：表格、代码块、参数、阈值、路径、状态码、错误码属于契约性事实，精简时禁止改写或省略。
